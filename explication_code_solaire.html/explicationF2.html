☀️ Documentation Frontend — Solar Energy

Documentation technique des composants React, de la navigation, de l'authentification, de la gestion des devis, des rendez-vous et des paiements Stripe.

📅 Dashboard des rendez-vous

DashboardAppointments.jsx est le composant React utilisé par l'administration pour consulter les rendez-vous pris par les clients. Il récupère les rendez-vous depuis le backend à l'aide d'Axios, les stocke dans un état local avec useState, puis les affiche sous forme de cartes.

Le composant permet ainsi à l'administrateur de consulter les principales informations associées à chaque rendez-vous, notamment le nom du client, son adresse e-mail, son numéro de téléphone, la date souhaitée, son adresse, son message et le statut du rendez-vous.

Gestion de l'état

Le composant utilise useState pour créer deux états. La variable appointments contient la liste des rendez-vous récupérés depuis l'API et est initialisée avec un tableau vide. La variable loading indique si les données sont encore en cours de chargement.

Ces états permettent à React de mettre automatiquement à jour l'interface lorsque les rendez-vous sont récupérés ou lorsqu'une erreur survient pendant la communication avec le backend.

Récupération des rendez-vous

Le hook useEffect est exécuté automatiquement lorsque le composant est chargé. Il appelle la fonction fetchAppointments(), qui envoie une requête HTTP GET vers l'endpoint /api/appointments.

Cette requête permet de récupérer les rendez-vous enregistrés dans la base de données et de les afficher dans le dashboard d'administration.

Authentification de l'administrateur

Avant d'envoyer la requête, le composant récupère le token d'authentification depuis localStorage grâce à localStorage.getItem("token").

Le token est ensuite envoyé au backend dans l'en-tête Authorization avec le format Bearer token. Cela permet au backend de vérifier l'identité de l'utilisateur avant de retourner les données.

Traitement de la réponse API

Après réception de la réponse, le composant vérifie plusieurs structures possibles de données. Il peut récupérer directement un tableau depuis response.data, depuis response.data.data ou depuis response.data.appointments.

Cette vérification permet au composant de rester compatible avec différentes structures de réponse du backend.

Gestion des erreurs

Les erreurs sont capturées avec un bloc try...catch. Lorsqu'une erreur survient, elle est affichée dans la console avec console.error() et la liste des rendez-vous est réinitialisée avec un tableau vide.

Affichage du statut

La fonction getAppointmentStatusLabel() transforme les statuts techniques provenant du backend en libellés plus compréhensibles pour l'administrateur.

Par exemple, Pending devient « En attente », Confirmed devient « Confirmé », Rejected devient « Refusé » et Cancelled devient « Annulé ».

Affichage des rendez-vous

Les rendez-vous sont parcourus avec la méthode .map(). Pour chaque rendez-vous, le composant crée une carte contenant les informations du client.

La propriété appointment._id est utilisée comme clé unique pour permettre à React d'identifier chaque élément. La date est convertie avec new Date(), puis affichée au format français grâce à toLocaleDateString("fr-FR").

💳 Dashboard des paiements

DashboardPayments.jsx est le composant React permettant à l'administration de consulter et de gérer les paiements enregistrés dans le système.

Il récupère les paiements depuis le backend, affiche les informations relatives au client et à la transaction et fournit plusieurs actions permettant de modifier ou de supprimer un paiement.

Gestion de l'état

Le composant utilise deux états principaux. La variable payments contient la liste des paiements récupérés depuis l'API tandis que loading indique si les paiements sont encore en cours de récupération.

Récupération des paiements

Le hook useEffect appelle la fonction fetchPayments() lors du chargement du composant. Cette fonction envoie une requête HTTP GET vers /api/payments.

Lorsque les données sont reçues, elles sont enregistrées dans l'état payments. React actualise ensuite automatiquement l'interface afin d'afficher les paiements.

Compteur des paiements

Le nombre de paiements est calculé avec payments.length. Le composant affiche ainsi dynamiquement le nombre total de paiements reçus.

Le texte est également adapté automatiquement entre « paiement » et « paiements » selon le nombre enregistré.

Modification du statut

La fonction updateStatus() permet à l'administrateur de modifier le statut d'un paiement. Elle envoie une requête HTTP PUT vers /api/payments/:id avec le nouveau statut.

Cette fonctionnalité permet notamment de confirmer un paiement avec le statut Paid ou de le marquer comme échoué avec le statut Failed.

Suppression d'un paiement

La fonction deletePayment() permet de supprimer un paiement. Avant la suppression, window.confirm() affiche une demande de confirmation afin d'éviter une suppression accidentelle.

Si l'administrateur confirme la suppression, une requête HTTP DELETE est envoyée vers /api/payments/:id. Après la suppression, la liste des paiements est actualisée avec fetchPayments().

Affichage des statuts

Le composant utilise plusieurs conditions pour afficher un libellé différent selon le statut enregistré dans la base de données. Le statut Paid représente un paiement confirmé, Pending un paiement en attente, Failed un paiement échoué et Refunded un paiement remboursé.

Actions administratives

Les boutons d'action sont affichés dynamiquement. Le bouton « Confirmer paiement » apparaît lorsque le paiement n'est pas encore marqué comme Paid. Le bouton « Refuser » apparaît lorsque le paiement n'est pas encore marqué comme Failed.

Un bouton « Supprimer » reste disponible afin de permettre à l'administrateur de supprimer le paiement après confirmation.

🏠 Page d'accueil

Home.jsx représente la page d'accueil principale de l'application Solar Energy. Ce composant reste volontairement simple puisqu'il assemble plusieurs composants React existants afin de construire l'interface d'accueil.

Il affiche principalement le composant Auth ainsi que le composant Testimonials.

Composant Auth

Le composant Auth est intégré directement dans la page avec <Auth />. Il permet de gérer l'authentification des utilisateurs, notamment la connexion et l'inscription selon l'implémentation du composant.

Composant Testimonials

Le composant Testimonials permet d'afficher les témoignages ou avis des clients. Il est placé après le système d'authentification afin de présenter aux visiteurs les retours concernant les services proposés par Solar Energy.

📋 Page « Mes demandes de devis »

MyQuotes.jsx permet à un client connecté de consulter ses demandes de devis. Le composant récupère les devis depuis le backend grâce à Axios et utilise le token d'authentification enregistré dans localStorage.

Chaque devis est ensuite affiché avec ses informations principales ainsi que son statut actuel.

Vérification de l'authentification

Avant de récupérer les devis, le composant vérifie la présence du token dans localStorage. Si aucun token n'est trouvé, un message informe l'utilisateur qu'il doit se connecter et celui-ci est redirigé vers /auth.

Cette vérification permet d'éviter qu'un utilisateur non connecté tente d'accéder à ses données personnelles.

Récupération des devis

La fonction fetchQuotes() envoie une requête HTTP GET vers /api/quotes. Le token est transmis dans l'en-tête Authorization.

Le backend peut ainsi identifier l'utilisateur authentifié et retourner les informations correspondant à ses demandes de devis.

Affichage des informations du devis

Chaque devis contient plusieurs informations : nom du client, email, téléphone, adresse, type d'installation, consommation estimée, budget, message et statut.

Ces informations permettent au client de suivre l'évolution de sa demande depuis son envoi jusqu'à sa validation.

Gestion du statut du devis

Le composant adapte son affichage en fonction du statut du devis. Lorsque le statut est Pending, le client est informé que sa demande est encore en attente de validation.

Lorsque le statut est Reviewed, il est informé que l'administration a consulté sa demande. Lorsque le statut est Rejected, il est informé que la demande a été refusée.

Enfin, lorsque le statut est Approved, le client peut procéder au paiement du montant indiqué dans son devis.

Paiement Stripe depuis un devis accepté

Lorsque le devis possède le statut Approved, le composant affiche un bouton permettant au client de payer avec Stripe.

La fonction handleStripePayment() vérifie d'abord l'identifiant du devis, le nom du client, son adresse e-mail ainsi que le montant avant d'envoyer les informations au backend.

Création de la session Stripe

Les informations du devis sont envoyées au backend avec une requête HTTP POST. Le backend est responsable de créer la session de paiement Stripe et de retourner une URL permettant d'accéder à la page de paiement.

Lorsque l'URL Stripe est reçue correctement, window.location.href redirige automatiquement le navigateur du client vers la page de paiement.

💳 Page de paiement

Payment.jsx est une page dédiée au paiement d'un devis spécifique. L'identifiant du devis est récupéré directement depuis l'URL grâce à useParams().

Le composant récupère ensuite les informations du devis depuis le backend et affiche les informations nécessaires avant de permettre au client de procéder au paiement.

Récupération du quoteId

La ligne const { quoteId } = useParams() permet de récupérer l'identifiant présent dans la route /payment/:quoteId.

Cet identifiant est ensuite utilisé pour demander au backend les informations du devis correspondant.

Récupération du devis

La fonction fetchQuote() envoie une requête HTTP GET vers /api/quotes/${quoteId}.

Le token de l'utilisateur est transmis dans l'en-tête Authorization. Le backend retourne ensuite les informations du devis demandé.

Vérification du statut

Avant de lancer le paiement, le composant vérifie que le devis possède le statut Approved.

Si le devis n'est pas encore accepté, le paiement est bloqué et un message informe le client qu'il doit attendre la validation de son devis.

Préparation du paiement

La fonction handleStripePayment() récupère le nom du client, son email et le budget du devis.

Le montant est converti en nombre avec Number(quote.budget) afin d'être transmis correctement au backend.

Redirection vers Stripe

Après l'appel à l'API /api/payments/create-checkout-session, le composant vérifie si le backend a retourné une réponse contenant success et une url.

Si ces deux informations sont présentes, le navigateur est redirigé vers la page de paiement Stripe avec window.location.href.

☀️ Page des produits solaires

Products.jsx affiche les produits solaires disponibles dans l'application. Il récupère trois catégories de produits depuis le backend : les panneaux solaires, les batteries et les onduleurs.

Les données des trois catégories sont ensuite regroupées dans un seul tableau afin de pouvoir être affichées dans une interface commune.

Récupération des produits

Le composant utilise Promise.all() pour envoyer simultanément trois requêtes HTTP vers /api/panels, /api/batteries et /api/inverters.

Cette méthode permet de récupérer les trois catégories en parallèle au lieu d'attendre la fin de chaque requête séparément.

Regroupement des produits

Après réception des trois réponses, les données sont regroupées avec l'opérateur de décomposition ....

Chaque produit reçoit également une propriété category permettant d'identifier son type. Les panneaux reçoivent la catégorie « Panneau solaire », les batteries « Batterie solaire » et les onduleurs « Onduleur solaire ».

Recherche de produits

La variable search contient le texte saisi par l'utilisateur dans la barre de recherche.

La méthode .filter() permet ensuite de conserver uniquement les produits correspondant à la recherche. Le système recherche notamment dans le nom, la marque, la catégorie, la technologie et le type.

Affichage des produits

Chaque produit est affiché sous forme de carte contenant son image, son nom, sa catégorie, sa marque, ses caractéristiques techniques, sa description et son prix.

Certaines informations sont affichées uniquement lorsqu'elles existent grâce à des conditions comme product.power &&.

Gestion du stock

La propriété inStock permet de déterminer si le produit est disponible.

Lorsque le produit est disponible, l'interface affiche « En stock ». Lorsqu'il n'est pas disponible, elle affiche « Rupture » et le bouton de demande de devis est désactivé.

Navigation vers le devis

Lorsque le client clique sur « Demander un devis », la fonction navigate() de React Router redirige l'utilisateur vers /quote.

Le produit sélectionné est également transmis dans l'état de navigation avec state: { product: product }, ce qui permet à la page de devis de connaître le produit sélectionné.

Déconnexion

La fonction handleLogout() supprime le token et les informations de l'utilisateur enregistrés dans localStorage.

Elle affiche ensuite un message de confirmation et redirige l'utilisateur vers la page d'authentification.

📄 Formulaire de demande de devis

Quote.jsx permet au client de remplir un formulaire afin de demander une estimation pour une installation solaire. Le formulaire collecte les informations personnelles du client ainsi que les informations relatives à son projet.

Gestion du formulaire

Les données du formulaire sont stockées dans l'état form avec useState.

Chaque champ possède une propriété correspondant à une information précise : customerName, email, phone, address, serviceType, estimatedConsumption, budget et message.

Modification des champs

La fonction handleChange() récupère le nom et la valeur du champ modifié grâce à e.target.

Elle utilise ensuite la syntaxe ...prev afin de conserver les autres valeurs du formulaire et de modifier uniquement le champ concerné.

Validation des données

Avant l'envoi, la fonction handleSubmit() vérifie que les champs obligatoires sont renseignés.

Le nom, l'email, le téléphone, l'adresse, le type d'installation et la consommation estimée sont nécessaires pour envoyer correctement une demande de devis.

Préparation des données

Avant d'envoyer les données au backend, les valeurs numériques sont converties avec Number().

La consommation estimée est convertie en nombre et le budget est également converti lorsqu'il a été renseigné. Cela permet au backend de recevoir des données adaptées au modèle de données.

Envoi vers le backend

Le formulaire envoie une requête HTTP POST vers /api/quotes avec Axios.

Dans le code présenté, cette requête est envoyée sans token. Le backend reçoit alors les informations du formulaire et crée la demande de devis dans la base de données.

Actions supplémentaires

La page contient également trois actions de navigation. Le bouton « Contacter Solar Energy » redirige vers /contact, le bouton « Prendre un rendez-vous » redirige vers /appointments et le bouton « Voir mes devis » redirige vers /my-quotes.

⭐ Page des avis clients

Reviews.jsx affiche une liste d'avis clients. Dans la version actuelle, les avis sont directement stockés dans un tableau JavaScript appelé reviews.

Chaque élément du tableau contient le nom du client, une note sur cinq et un commentaire.

Affichage des avis

La méthode .map() parcourt le tableau reviews et crée un élément HTML pour chaque avis.

Le composant affiche le nom du client, sa note et son commentaire. Dans cette implémentation, l'index du tableau est utilisé comme clé React.

🧭 Gestion des routes de l'application

AppRoutes.jsx constitue le système central de navigation de l'application. Il utilise Routes, Route et Navigate de React Router afin de définir les différentes pages accessibles dans l'application Solar Energy.

Routes client

Les routes /products, /quote, /contact, /appointments, /my-quotes et /payment/:quoteId correspondent aux fonctionnalités destinées aux clients.

Elles sont placées à l'intérieur du composant Layout, ce qui permet de partager une structure commune entre les différentes pages.

Routes protégées

Les pages privées sont enveloppées dans le composant PrivateRoute. Celui-ci vérifie la présence d'un token dans localStorage.

Si le token existe, l'utilisateur peut accéder à la page. Dans le cas contraire, il est redirigé vers la page d'accueil.

Routes administrateur

Les routes /dashboard, /dashboard-contacts, /dashboard-appointments et /dashboard-payments correspondent à l'espace d'administration.

Elles utilisent AdminLayout afin de partager une structure commune à l'ensemble des pages administratives.

Route inconnue

La route * capture toutes les URL qui ne correspondent à aucune route définie.

Dans ce cas, l'utilisateur est automatiquement redirigé vers la page d'accueil avec Navigate.

🔐 Protection des routes privées

PrivateRoute.jsx est un composant utilisé pour protéger les pages nécessitant une authentification. Il vérifie si un token est présent dans localStorage.

Vérification du token

La méthode localStorage.getItem("token") permet de récupérer le token enregistré lors de la connexion.

Si aucun token n'est trouvé, le composant utilise Navigate pour rediriger l'utilisateur vers /.

Si un token existe, le composant retourne children et autorise l'affichage de la page demandée.

Rôle de PrivateRoute

Le rôle de PrivateRoute est principalement de contrôler l'accès aux pages du côté frontend. Il empêche un utilisateur non connecté d'afficher certaines pages directement depuis le navigateur.

Important :
La sécurité réelle des données doit également être assurée par le backend. Le serveur doit vérifier la validité du token avant d'autoriser l'accès aux données protégées.

🌐 Protection des routes publiques

PublicRoute.jsx est destiné aux pages accessibles principalement aux utilisateurs qui ne sont pas encore connectés, comme une page d'authentification.

Redirection des utilisateurs connectés

Le composant vérifie la présence d'un token dans localStorage.

Si un token existe, l'utilisateur est automatiquement redirigé vers /dashboard. Si aucun token n'existe, le composant affiche le contenu fourni dans children.

🧩 Layout principal de l'application

Layout.jsx définit la structure commune des pages client. Il utilise le composant Outlet de React Router pour afficher dynamiquement la page correspondant à la route actuelle.

Utilisation de Outlet

Outlet représente l'emplacement dans lequel React Router insère le composant correspondant à la route active.

Cela permet de conserver une structure commune tout en changeant uniquement le contenu principal de chaque page.

Gestion du Footer

Le composant utilise useLocation() pour connaître l'URL actuelle.

La variable hideFooter devient vraie lorsque l'utilisateur se trouve sur /auth. Dans ce cas, le Footer n'est pas affiché.

Sur les autres pages, le Footer est rendu automatiquement.

⚛️ Point d'entrée de l'application React

App.jsx constitue le point d'entrée principal de la navigation React. Il enveloppe l'application dans BrowserRouter afin d'activer le système de routage de React Router.

BrowserRouter

BrowserRouter permet à React Router de gérer les différentes URL de l'application sans recharger complètement la page.

Il fournit le contexte de navigation nécessaire à Routes, Route, Navigate, useNavigate, useParams et useLocation.

AppRoutes

Le composant <AppRoutes /> contient toutes les routes de l'application.

App.jsx reste donc très simple : il initialise le système de routage et délègue la définition des différentes pages à AppRoutes.

🏗️ Architecture globale de l'application Solar Energy

L'application Solar Energy repose sur une architecture frontend/backend séparée.

Le frontend est développé avec React. Il est responsable de l'interface utilisateur, des formulaires, de la navigation, de l'affichage des données et de la gestion des états locaux.

Axios assure la communication entre les composants React et les différentes API du backend.

Le backend Node.js avec Express traite les requêtes, applique la logique métier et communique avec MongoDB pour enregistrer et récupérer les données.

Les principales données manipulées par l'application concernent les utilisateurs, les produits solaires, les devis, les rendez-vous, les contacts et les paiements.

👤 Flux d'un client

Un client commence par accéder à la page d'accueil et peut s'authentifier. Une fois connecté, il peut consulter les produits solaires, rechercher un panneau, une batterie ou un onduleur, puis demander un devis.

Il peut également prendre un rendez-vous ou contacter Solar Energy. Ses demandes de devis sont ensuite accessibles depuis la page « Mes devis ».

📄 Flux du devis

Le client remplit le formulaire de demande de devis et les informations sont envoyées au backend avec une requête HTTP POST.

La demande est ensuite enregistrée avec un statut initial, généralement Pending. L'administration peut consulter la demande et modifier son statut.

Lorsque le devis est approuvé avec le statut Approved, le client peut procéder au paiement.

💳 Flux du paiement Stripe

Après l'approbation du devis, le client peut cliquer sur le bouton de paiement. React envoie les informations du devis au backend.

Le backend crée ensuite une session de paiement Stripe et retourne une URL de paiement au frontend.

React utilise alors window.location.href pour rediriger automatiquement le navigateur du client vers Stripe afin qu'il puisse effectuer son paiement.

👨‍💼 Flux de l'administration

L'administration dispose de plusieurs tableaux de bord permettant de gérer les différentes informations de l'application.

Le dashboard des contacts permet de consulter les messages reçus. Le dashboard des rendez-vous permet de consulter les rendez-vous clients. Le dashboard des paiements permet de consulter, confirmer, refuser ou supprimer les paiements.

🔐 Sécurité et authentification

L'application utilise un token enregistré dans localStorage afin de maintenir l'authentification côté frontend.

Les composants nécessitant une authentification récupèrent ce token et l'envoient au backend dans l'en-tête Authorization avec le format Bearer.

Le composant PrivateRoute contrôle également la présence du token avant d'autoriser l'accès aux pages privées.

🔄 Communication Frontend / Backend

La communication entre React et le backend est principalement réalisée avec Axios.

Les requêtes HTTP GET permettent de récupérer les données, les requêtes POST permettent de créer des ressources, les requêtes PUT permettent de modifier des informations et les requêtes DELETE permettent de supprimer des données.

Cette architecture permet de séparer clairement l'interface utilisateur, la logique métier et la gestion des données. Le frontend se concentre sur l'expérience utilisateur tandis que le backend assure le traitement des données et la communication avec la base de données.
