☀️ Documentation Frontend — Solar Energy

Explication des composants React, Axios, React Router, authentification, rendez-vous, contacts, avis et Dashboard Admin.

📚 1. Présentation générale

Cette partie du projet correspond au Frontend React de la plateforme Solar Energy.

Les composants présentés permettent aux utilisateurs de créer un compte, se connecter, envoyer un message, demander un rendez-vous et consulter les avis.

Le système possède également un Dashboard Admin permettant de consulter les statistiques et de gérer les demandes de devis.

Technologies utilisées :
  • React.js
  • React Hooks (useState, useEffect)
  • Axios pour les requêtes HTTP
  • React Router
  • LocalStorage pour le JWT
  • API REST Node.js / Express
  • MongoDB côté Backend

⭐ 2. Composant Testimonials.jsx

Le composant Testimonials.jsx permet d'afficher les avis clients enregistrés dans la base de données.

2.1 Importation des dépendances 

import { useEffect, useState } from "react";
import axios from "axios";
import "./Testimonials.css";

useState permet de créer et modifier l'état local du composant.

useEffect permet d'exécuter du code automatiquement après le chargement du composant.

axios permet de communiquer avec l'API Backend.

2.2 Stockage des avis 

const [reviews, setReviews] = useState([]);

Au départ, la liste des avis est vide. La fonction setReviews permet ensuite de mettre à jour cette liste.

2.3 Récupération des avis 

useEffect(() => {

    axios
        .get("http://localhost:3000/api/reviews")

        .then((res) => {

            console.log(
                "API REVIEWS :",
                res.data
            );

        })

        .catch((error) => {

            console.log(
                "Erreur API :",
                error
            );

        });

}, []);

Lorsque la page est chargée, une requête GET est envoyée vers : 

GET /api/reviews

Le Backend retourne les avis disponibles.

2.4 Filtrage des avis approuvés 

res.data.data.filter(
    review => review.status === "Approved"
)

Le composant n'affiche que les avis dont le statut est Approved.

Pourquoi ?

Les avis peuvent être créés par les clients, mais ils doivent être validés par l'administrateur avant d'être affichés publiquement.

2.5 Affichage des étoiles 

{"⭐".repeat(review.rating)}

Si la note est 5, React génère :

⭐⭐⭐⭐⭐

2.6 Affichage de l'avis 

{reviews.map(review => (

    <div
        className="review-card"
        key={review._id}
    >

        <h3>
            {review.customerName}
        </h3>

        <p>
            {"⭐".repeat(review.rating)}
        </p>

        <p>
            {review.comment}
        </p>

        <strong>
            {review.productName}
        </strong>

    </div>

))}

map() parcourt tous les avis et crée une carte HTML pour chaque avis.

📅 4. Composant Appointment.jsx

Le composant Appointment permet au client de demander un rendez-vous avec Solar Energy.

4.1 États du formulaire 

const [form, setForm] = useState({

    customerName: "",
    email: "",
    phone: "",
    appointmentDate: "",
    address: "",
    message: "",

});

L'objet form contient toutes les informations saisies par le client.

4.2 État loading 

const [loading, setLoading] = useState(false);

Cette variable permet de savoir si la requête est actuellement en cours.

4.3 Modification du formulaire 

const handleChange = (e) => {

    const { name, value } = e.target;

    setForm((prev) => ({
        ...prev,
        [name]: value,
    }));

};

Cette fonction récupère le nom du champ et sa valeur.

Par exemple, si l'utilisateur écrit Ahmed dans le champ customerName, React met à jour : 

form.customerName = "Ahmed"

4.4 Envoi du rendez-vous 

const response = await axios.post(
    "http://localhost:3000/api/appointments",
    {
        customerName: form.customerName,
        email: form.email,
        phone: form.phone,
        appointmentDate: form.appointmentDate,
        address: form.address,
        message: form.message,
    }
);

Lors de l'envoi, Axios effectue une requête POST vers : 

POST /api/appointments

4.5 Réinitialisation du formulaire 

setForm({
    customerName: "",
    email: "",
    phone: "",
    appointmentDate: "",
    address: "",
    message: "",
});

Après un envoi réussi, tous les champs sont vidés.

4.6 Navigation 

navigate("/quote");

Après la création du rendez-vous, l'utilisateur est redirigé vers la page /quote.

4.7 Date minimale 

min={
    new Date()
        .toISOString()
        .split("T")[0]
}

Cette instruction empêche l'utilisateur de sélectionner une date située dans le passé.

4.8 Bouton dynamique 

{loading
    ? "⏳ Envoi en cours..."
    : "📅 Demander un rendez-vous"}

Pendant l'envoi, le bouton indique que la requête est en cours et est désactivé.

🔐 5. Composant Auth.jsx

Le composant Auth gère à la fois l'inscription et la connexion des utilisateurs.

5.1 Mode connexion / inscription 

const [mode, setMode] = useState("login");

Le mode initial est login.

Lorsque le mode est register, le formulaire affiche également le champ Nom.

5.2 Données du formulaire 

const [form, setForm] = useState({

    name: "",
    email: "",
    password: "",

});

5.3 Connexion 

const response = await axios.post(
    "http://localhost:3000/api/users/login",
    {
        email: form.email,
        password: form.password,
    }
);

Une requête POST est envoyée au Backend pour vérifier l'adresse email et le mot de passe.

5.4 Récupération du JWT 

if (response.data.token) {

    localStorage.setItem(
        "token",
        response.data.token
    );

}

Si la connexion est réussie, le Backend retourne un JWT.

Le token est ensuite enregistré dans localStorage.

Flux d'authentification :
Utilisateur → Login → Backend → Vérification → JWT → localStorage

5.5 Redirection après connexion 

navigate("/products");

Après une connexion réussie, l'utilisateur est redirigé vers la page des produits.

5.6 Inscription 

await axios.post(
    "http://localhost:3000/api/users/register",
    {
        name: form.name,
        email: form.email,
        password: form.password,
    }
);

Le formulaire d'inscription envoie le nom, l'email et le mot de passe au Backend.

5.7 Retour vers la connexion 

setMode("login");

Après la création du compte, le formulaire revient automatiquement au mode connexion.

5.8 Changement Login / Register 

setMode(
    mode === "login"
        ? "register"
        : "login"
);

Cette logique permet à l'utilisateur de passer de la connexion à l'inscription et inversement.

📊 7. Dashboard.jsx

Le composant Dashboard représente le tableau de bord administrateur de Solar Energy.

Il permet notamment de consulter les statistiques générales et les demandes de devis.

7.1 État des statistiques 

const [stats, setStats] = useState({

    users: 0,
    panels: 0,
    batteries: 0,
    inverters: 0,
    appointments: 0,
    quotes: 0,
    payments: 0,
    contacts: 0,
    reviews: 0,

});

Le Dashboard possède plusieurs indicateurs :

  • 👥 Utilisateurs
  • ☀️ Panneaux
  • 🔋 Batteries
  • ⚡ Onduleurs
  • 📅 Rendez-vous
  • 📄 Demandes de devis
  • 💳 Paiements
  • 📩 Contacts
  • ⭐ Avis

7.2 Chargement initial 

useEffect(() => {

    fetchDashboard();

    fetchQuotes();

}, []);

Au chargement du Dashboard, deux fonctions sont exécutées :

  • fetchDashboard() pour les statistiques
  • fetchQuotes() pour les devis

7.3 Récupération du token 

const token =
    localStorage.getItem("token");

Le token JWT enregistré lors de la connexion est récupéré depuis localStorage.

7.4 Authentification de la requête 

headers: {

    Authorization:
        `Bearer ${token}`,

}

Le token est envoyé dans l'en-tête HTTP Authorization.

Important :

Le Backend peut ainsi vérifier que la requête provient d'un utilisateur authentifié.

7.5 API Dashboard 

axios.get(
    "http://localhost:3000/api/dashboard",
    {
        headers: {
            Authorization:
                `Bearer ${token}`,
        },
    }
);

7.6 Traitement de la réponse 

if (
    response.data &&
    response.data.success &&
    response.data.data
) {

    const data =
        response.data.data;

    setStats({

        users: data.users || 0,

        panels: data.panels || 0,

        batteries:
            data.batteries || 0,

        inverters:
            data.inverters || 0,

        appointments:
            data.appointments || 0,

        quotes:
            data.quotes || 0,

        payments:
            data.payments || 0,

        contacts:
            data.contacts || 0,

        reviews:
            data.reviews || 0,

    });

}

7.7 Récupération des devis

La fonction fetchQuotes() récupère les demandes de devis. 

const response = await axios.get(
    "http://localhost:3000/api/quotes",
    {
        headers: {
            Authorization:
                `Bearer ${token}`,
        },
    }
);

7.8 Gestion de plusieurs formats API

Le code accepte plusieurs formats de réponse : 

// Format 1
[ {...}, {...} ]

// Format 2
{ data: [...] }

// Format 3
{ quotes: [...] }

// Format 4
{ data: { quotes: [...] } }

Cette logique rend le composant plus flexible lorsque la structure de la réponse Backend change.

7.9 Modification du statut d'un devis 

const updateQuoteStatus =
    async (id, status) => {

    const response =
        await axios.put(
            `http://localhost:3000/api/quotes/${id}`,
            {
                status: status,
            },
            {
                headers: {
                    Authorization:
                        `Bearer ${token}`,
                },
            }
        );

};

L'administrateur peut modifier le statut d'un devis.

7.10 Statuts disponibles

  • Pending — En attente
  • Reviewed — Demande consultée
  • Approved — Acceptée
  • Rejected — Refusée

7.11 Logique des actions

Pending

👁️ Consultée → Reviewed

✅ Accepter → Approved

❌ Refuser → Rejected

Reviewed

✅ Accepter → Approved

❌ Refuser → Rejected

Approved :

Le Dashboard indique que le devis est accepté et que le client peut maintenant effectuer son paiement.

Rejected :

Le Dashboard affiche que le devis a été refusé.

📩 8. DashboardContacts.jsx

Le composant DashboardContacts permet à l'administrateur de consulter les messages envoyés depuis le formulaire Contact.

8.1 État des contacts 

const [contacts, setContacts] =
    useState([]);

const [loading, setLoading] =
    useState(true);

8.2 Chargement automatique 

useEffect(() => {

    fetchContacts();

}, []);

Dès que la page est chargée, fetchContacts() est exécutée.

8.3 Vérification du token 

const token =
    localStorage.getItem("token");

if (!token) {

    setContacts([]);

    setLoading(false);

    return;

}

L'accès aux messages nécessite un token d'authentification.

8.4 Requête API 

const res = await axios.get(
    "http://localhost:3000/api/contacts",
    {
        headers: {
            Authorization:
                `Bearer ${token}`,
        },
    }
);

Le composant appelle : 

GET /api/contacts

8.5 Extraction des contacts

Comme pour les devis, plusieurs formats de réponse sont pris en charge. 

// Format 1
[ {...}, {...} ]

// Format 2
{ data: [...] }

// Format 3
{ contacts: [...] }

// Format 4
{ data: { contacts: [...] } }

8.6 Compteur des messages 

{contacts.length}

contacts.length indique le nombre total de messages récupérés.

Exemple : 

5 messages

8.7 Affichage des informations

Chaque message est affiché dans une carte. 

{contacts.map((contact) => (

    <div
        className="contact-card"
        key={contact._id}
    >

        ...

    </div>

))}

8.8 Informations affichées

  • 👤 Nom du client
  • 📧 Email
  • 📱 Téléphone
  • 📌 Sujet
  • 💬 Message
  • 📊 Statut
  • 📅 Date

8.9 Gestion du nom 

contact.fullName ||
contact.name ||
"Client"

Le composant essaie d'abord d'utiliser fullName. Si cette propriété n'existe pas, il utilise name. Sinon, il affiche Client.

8.10 Gestion d'une erreur 401 

if (
    error.response?.status === 401
) {

    alert(
        "Session expirée. Veuillez vous reconnecter."
    );

    localStorage.removeItem(
        "token"
    );

    window.location.href =
        "/auth";
}

Le code vérifie si le Backend retourne le statut HTTP 401.

Cela signifie généralement que le token est absent, invalide ou expiré.

Dans ce cas :

  1. Un message est affiché.
  2. Le token est supprimé.
  3. L'utilisateur est redirigé vers /auth.

🔄 9. Fonctionnement global du Frontend

Les différents composants communiquent avec le Backend grâce aux API REST.

👤 Utilisateur

↓

React

↓

Axios

↓

API Express

↓

MongoDB

Principales API utilisées

  • POST /api/users/register — inscription
  • POST /api/users/login — connexion
  • GET /api/reviews — récupération des avis
  • POST /api/appointments — création d'un rendez-vous
  • POST /api/contacts — création d'un message
  • GET /api/dashboard — statistiques administrateur
  • GET /api/quotes — récupération des devis
  • PUT /api/quotes/:id — modification du statut d'un devis
  • GET /api/contacts — récupération des messages

🔑 10. Authentification JWT

Le système utilise un token JWT pour protéger certaines routes administrateur.

1. L'utilisateur se connecte.

↓

2. Le Backend vérifie ses identifiants.

↓

3. Le Backend génère un JWT.

↓

4. React stocke le JWT dans localStorage.

↓

5. Axios envoie le JWT avec les requêtes protégées.

↓

6. Le Middleware Backend vérifie le token. 

Authorization: Bearer TOKEN
