📅 Dashboard de agendamentos

DashboardAppointments.jsx é o componente React utilizado pela administração para consultar os agendamentos realizados pelos clientes. Ele recupera os agendamentos do backend usando Axios, armazena-os no estado local com useState e depois os exibe em forma de cartões.

O componente permite que o administrador consulte as principais informações associadas a cada agendamento, incluindo o nome do cliente, endereço de e-mail, número de telefone, data desejada, endereço, mensagem e status do agendamento.

Gerenciamento do estado

O componente utiliza useState para criar dois estados. A variável appointments contém a lista de agendamentos recuperados da API e é inicializada com um array vazio. A variável loading indica se os dados ainda estão sendo carregados.

Esses estados permitem que o React atualize automaticamente a interface quando os agendamentos são recuperados ou quando ocorre um erro durante a comunicação com o backend.

Recuperação dos agendamentos

O hook useEffect é executado automaticamente quando o componente é carregado. Ele chama a função fetchAppointments(), que envia uma requisição HTTP GET para o endpoint /api/appointments.

Essa requisição permite recuperar os agendamentos armazenados no banco de dados e exibi-los no dashboard administrativo.

Autenticação do administrador

Antes de enviar a requisição, o componente recupera o token de autenticação do localStorage usando localStorage.getItem("token").

O token é então enviado ao backend no cabeçalho Authorization usando o formato Bearer token. Isso permite que o backend verifique a identidade do usuário antes de retornar os dados.

Processamento da resposta da API

Após receber a resposta, o componente verifica várias estruturas possíveis de dados. Ele pode recuperar um array diretamente de response.data, de response.data.data ou de response.data.appointments.

Essa verificação permite que o componente permaneça compatível com diferentes estruturas de resposta do backend.

Tratamento de erros

Os erros são capturados usando um bloco try...catch. Quando ocorre um erro, ele é exibido no console usando console.error(), e a lista de agendamentos é redefinida para um array vazio.

Exibição do status

A função getAppointmentStatusLabel() transforma os status técnicos recebidos do backend em rótulos mais compreensíveis para o administrador.

Por exemplo, Pending se torna "Pendente", Confirmed se torna "Confirmado", Rejected se torna "Recusado" e Cancelled se torna "Cancelado".

Exibição dos agendamentos

Os agendamentos são percorridos usando o método .map(). Para cada agendamento, o componente cria um cartão contendo as informações do cliente.

A propriedade appointment._id é utilizada como uma chave única para permitir que o React identifique cada elemento. A data é convertida usando new Date() e depois exibida no formato francês usando toLocaleDateString("fr-FR").

💳 Dashboard de pagamentos

DashboardPayments.jsx é o componente React que permite à administração consultar e gerenciar os pagamentos registrados no sistema.

Ele recupera os pagamentos do backend, exibe informações relacionadas ao cliente e à transação e fornece várias ações para modificar ou excluir um pagamento.

Gerenciamento do estado

O componente utiliza dois estados principais. A variável payments contém a lista de pagamentos recuperados da API, enquanto loading indica se os pagamentos ainda estão sendo recuperados.

Recuperação dos pagamentos

O hook useEffect chama a função fetchPayments() quando o componente é carregado. Essa função envia uma requisição HTTP GET para /api/payments.

Quando os dados são recebidos, eles são armazenados no estado payments. O React atualiza automaticamente a interface para exibir os pagamentos.

Contador de pagamentos

O número de pagamentos é calculado usando payments.length. Dessa forma, o componente exibe dinamicamente o número total de pagamentos recebidos.

O texto também é adaptado automaticamente entre "pagamento" e "pagamentos" de acordo com o número registrado.

Alteração do status

A função updateStatus() permite que o administrador altere o status de um pagamento. Ela envia uma requisição HTTP PUT para /api/payments/:id com o novo status.

Essa funcionalidade permite confirmar um pagamento com o status Paid ou marcá-lo como falho com o status Failed.

Exclusão de um pagamento

A função deletePayment() permite excluir um pagamento. Antes da exclusão, window.confirm() exibe uma solicitação de confirmação para evitar uma exclusão acidental.

Se o administrador confirmar a exclusão, uma requisição HTTP DELETE é enviada para /api/payments/:id. Após a exclusão, a lista de pagamentos é atualizada usando fetchPayments().

Exibição dos status

O componente utiliza várias condições para exibir um rótulo diferente de acordo com o status armazenado no banco de dados. O status Paid representa um pagamento confirmado, Pending representa um pagamento pendente, Failed representa um pagamento com falha e Refunded representa um pagamento reembolsado.

Ações administrativas

Os botões de ação são exibidos dinamicamente. O botão "Confirmar pagamento" aparece quando o pagamento ainda não está marcado como Paid. O botão "Recusar" aparece quando o pagamento ainda não está marcado como Failed.

Um botão "Excluir" permanece disponível para permitir que o administrador exclua o pagamento após a confirmação.

📋 Página "Meus orçamentos"

MyQuotes.jsx permite que um cliente conectado consulte suas solicitações de orçamento. O componente recupera os orçamentos do backend usando Axios e utiliza o token de autenticação armazenado no localStorage.

Cada orçamento é exibido com suas principais informações e seu status atual.

Verificação da autenticação

Antes de recuperar os orçamentos, o componente verifica a presença do token no localStorage. Se nenhum token for encontrado, uma mensagem informa ao usuário que ele deve fazer login e o usuário é redirecionado para /auth.

Essa verificação impede que um usuário não conectado tente acessar seus dados pessoais.

Recuperação dos orçamentos

A função fetchQuotes() envia uma requisição HTTP GET para /api/quotes. O token é transmitido no cabeçalho Authorization.

O backend pode, portanto, identificar o usuário autenticado e retornar as informações correspondentes às suas solicitações de orçamento.

Exibição das informações do orçamento

Cada orçamento contém várias informações: nome do cliente, e-mail, telefone, endereço, tipo de instalação, consumo estimado, orçamento, mensagem e status.

Essas informações permitem que o cliente acompanhe a evolução de sua solicitação desde o envio até a aprovação.

Gerenciamento do status do orçamento

O componente adapta sua exibição de acordo com o status do orçamento. Quando o status é Pending, o cliente é informado de que sua solicitação ainda está aguardando validação.

Quando o status é Reviewed, o cliente é informado de que a administração analisou sua solicitação. Quando o status é Rejected, o cliente é informado de que a solicitação foi recusada.

Por fim, quando o status é Approved, o cliente pode prosseguir com o pagamento do valor indicado no orçamento.

Pagamento com Stripe a partir de um orçamento aprovado

Quando o orçamento possui o status Approved, o componente exibe um botão que permite ao cliente pagar usando Stripe.

A função handleStripePayment() verifica primeiro o ID do orçamento, o nome do cliente, seu endereço de e-mail e o valor antes de enviar as informações ao backend.

Criação da sessão do Stripe

As informações do orçamento são enviadas ao backend usando uma requisição HTTP POST. O backend é responsável por criar a sessão de pagamento do Stripe e retornar uma URL que permite acessar a página de pagamento.

Quando a URL do Stripe é recebida corretamente, window.location.href redireciona automaticamente o navegador do cliente para a página de pagamento.

💳 Página de pagamento

Payment.jsx é uma página dedicada ao pagamento de um orçamento específico. O ID do orçamento é recuperado diretamente da URL usando useParams().

O componente então recupera as informações do orçamento do backend e exibe as informações necessárias antes de permitir que o cliente prossiga com o pagamento.

Recuperação de quoteId

A linha const { quoteId } = useParams() recupera o identificador presente na rota /payment/:quoteId.

Esse identificador é então utilizado para solicitar ao backend as informações correspondentes ao orçamento.

Recuperação do orçamento

A função fetchQuote() envia uma requisição HTTP GET para /api/quotes/${quoteId}.

O token do usuário é transmitido no cabeçalho Authorization. O backend então retorna as informações solicitadas do orçamento.

Verificação do status

Antes de iniciar o pagamento, o componente verifica se o orçamento possui o status Approved.

Se o orçamento ainda não tiver sido aprovado, o pagamento é bloqueado e uma mensagem informa ao cliente que ele deve aguardar a aprovação do seu orçamento.

Preparação do pagamento

A função handleStripePayment() recupera o nome do cliente, seu e-mail e o orçamento.

O valor é convertido para um número usando Number(quote.budget) para que possa ser transmitido corretamente ao backend.

Redirecionamento para o Stripe

Após chamar a API /api/payments/create-checkout-session, o componente verifica se o backend retornou uma resposta contendo success e uma url.

Se essas duas informações estiverem presentes, o navegador será redirecionado para a página de pagamento do Stripe usando window.location.href.

☀️ Página de produtos solares

Products.jsx exibe os produtos solares disponíveis na aplicação. Ele recupera três categorias de produtos do backend: painéis solares, baterias e inversores.

Os dados das três categorias são então combinados em um único array para que possam ser exibidos por meio de uma interface comum.

Recuperação dos produtos

O componente utiliza Promise.all() para enviar simultaneamente três requisições HTTP para /api/panels, /api/batteries e /api/inverters.

Esse método permite recuperar as três categorias em paralelo, em vez de esperar que cada requisição termine separadamente.

Combinação dos produtos

Após receber as três respostas, os dados são combinados usando o operador spread ....

Cada produto também recebe uma propriedade category que identifica seu tipo. Os painéis recebem a categoria "Painel solar", as baterias recebem "Bateria solar" e os inversores recebem "Inversor solar".

Pesquisa de produtos

A variável search contém o texto digitado pelo usuário na barra de pesquisa.

O método .filter() é utilizado para manter apenas os produtos correspondentes à pesquisa. O sistema pesquisa principalmente no nome, marca, categoria, tecnologia e tipo.

Exibição dos produtos

Cada produto é exibido como um cartão contendo sua imagem, nome, categoria, marca, especificações técnicas, descrição e preço.

Algumas informações são exibidas apenas quando existem, usando condições como product.power &&.

Gerenciamento do estoque

A propriedade inStock permite determinar se o produto está disponível.

Quando o produto está disponível, a interface exibe "Em estoque". Quando não está disponível, exibe "Fora de estoque" e o botão de solicitação de orçamento fica desativado.
