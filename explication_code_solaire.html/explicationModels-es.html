Documentación técnica del Backend

Node.js • Express • MongoDB • Mongoose

1. Presentación del Backend

El backend de la plataforma Solar Energy está desarrollado con Node.js y Express.js.

Permite gestionar usuarios, productos solares, solicitudes de presupuesto, citas, contactos, pagos y reseñas de clientes.

Los datos se almacenan en una base de datos MongoDB y se gestionan mediante Mongoose.

2. Configuración del servidor Express

El archivo principal del backend inicializa Express, configura CORS, los middlewares y las diferentes rutas API.

Creación de la aplicación

const express = require("express");
const cors = require("cors");

const app = express();

express permite crear el servidor HTTP, mientras que cors permite las comunicaciones entre el frontend React y el backend.

3. Importación de las rutas

Cada funcionalidad dispone de su propio archivo de rutas. 

const appointmentRoutes = require("./routes/appointmentRoutes");
const batteryRoutes = require("./routes/batteryRoutes");
const contactRoutes = require("./routes/contactRoutes");
const dashboardRoutes = require("./routes/dashboardRoutes");
const inverterRoutes = require("./routes/inverterRoutes");
const panelRoutes = require("./routes/panelRoutes");
const paymentRoutes = require("./routes/paymentRoutes");

Esta organización permite separar las funcionalidades y facilita el mantenimiento del backend.

4. Configuración de CORS

app.use(
    cors({
        origin: "http://localhost:5173", 
        methods: ["GET", "POST", "PUT", "DELETE", "PATCH"], 
        credentials: true, 
    }) 
);

El frontend funciona aquí en el puerto 5173.

El middleware CORS autoriza las solicitudes HTTP provenientes de este origen.

5. Webhook de Stripe

El webhook de Stripe debe declararse antes de express.json(). 

app.post( 
    "/api/payments/webhook", 
    express.raw({ 
        type: "application/json", 
    }), 
    require("./controllers/paymentController").stripeWebhook 
);
``` Importante:

Stripe utiliza el cuerpo original de la solicitud para verificar correctamente la firma del webhook.

6. Middleware JSON

app.use(express.json()); 
 
app.use( 
    express.urlencoded({ 
        extended: true, 
    }) 
);

express.json() permite al servidor recibir datos en formato JSON.

express.urlencoded() permite procesar los datos enviados mediante formularios.

7. Rutas API

Las principales rutas del backend están organizadas por funcionalidad.

    ```
  • /api/appointments Gestión de citas.
  • /api/batteries Gestión de baterías.
  • /api/contacts Gestión de mensajes de contacto.
  • /api/dashboard Gestión de los datos del dashboard.
  • /api/inverters Gestión de inversores.
  • /api/panels Gestión de paneles solares.
  • /api/payments Gestión de pagos.
  • /api/quotes Gestión de solicitudes de presupuesto.
  • /api/reviews Gestión de reseñas de clientes.
  • /api/users Gestión de autenticación y usuarios.
    • ```

8. Modelo Appointment

El modelo Appointment representa una cita solicitada por un cliente. 

const appointmentSchema = new mongoose.Schema( 
    { 
        customerName: { 
            type: String, 
            required: true, 
        }, 
 
        email: { 
            type: String, 
            required: true, 
        }, 
 
        phone: { 
            type: String, 
            required: true, 
        }, 
 
        appointmentDate: { 
            type: Date, 
            required: true, 
        }, 
 
        address: { 
            type: String, 
            required: true, 
        }, 
 
        message: { 
            type: String, 
        }, 
 
        status: { 
            type: String, 
            enum: [ 
                "Pending", 
                "Confirmed", 
                "Completed", 
                "Cancelled" 
            ], 
            default: "Pending", 
        }, 
    }, 
    { 
        timestamps: true, 
    } 
); 
 
module.exports = mongoose.model( 
    "Appointment", 
    appointmentSchema 
);

El estado permite realizar un seguimiento de la evolución de la cita: pendiente, confirmada, completada o cancelada.

16. Modelo User

El modelo User gestiona las cuentas de usuario de la plataforma. 

const userSchema = new mongoose.Schema( 
    { 
        name: { 
            type: String, 
            required: true, 
            trim: true, 
        }, 
 
        email: { 
            type: String, 
            required: true, 
            unique: true, 
            lowercase: true,

            type: String, 
            required: true, 
        },

            type: String,

                "admin", 
                "customer" 
            ], 
            default: "customer",

            type: Boolean, 
            default: false,

    }, 
    { 
        timestamps: true, 
    } 
);

    "User", 
    userSchema 
);

El campo role distingue los dos tipos de usuarios:

  • admin: acceso a las funciones administrativas.
  • customer: acceso a las funciones de cliente.

El campo isVerified también permite saber si la cuenta del usuario ha sido verificada.

17. Gestión de rutas inexistentes

app.use((req, res) => { 
    res.status(404).json({ 
        success: false, 
        message: `Route introuvable : ${req.method} ${req.originalUrl}`, 
    }); 
});

Cuando una URL de la API no existe, el servidor devuelve una respuesta HTTP 404.

18. Gestión global de errores

app.use((err, req, res, next) => { 
 
    console.error("❌ Erreur serveur :", err); 
 
    res.status(err.status || 500).json({ 
        success: false, 
        message: err.message || "Erreur interne du serveur", 
    }); 
 
});

Este middleware permite capturar los errores generados durante el procesamiento de las solicitudes.

En caso de error interno, el servidor normalmente devuelve el código HTTP 500.

19. Conclusión

El backend de Solar Energy está organizado en torno a una arquitectura modular basada en Node.js, Express y MongoDB.

Los modelos Mongoose permiten estructurar los datos relacionados con usuarios, productos, presupuestos, citas, pagos, contactos y reseñas de clientes.

Las diferentes rutas API permiten que el frontend React se comunique con el backend y realice las operaciones necesarias para el funcionamiento de la plataforma.
