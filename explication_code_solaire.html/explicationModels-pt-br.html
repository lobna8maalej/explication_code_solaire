Documentação técnica do Backend

Node.js • Express • MongoDB • Mongoose

1. Apresentação do Backend

O backend da plataforma Solar Energy é desenvolvido com Node.js e Express.js.

Ele permite gerenciar usuários, produtos solares, solicitações de orçamento, agendamentos, contatos, pagamentos e avaliações dos clientes.

Os dados são armazenados em um banco de dados MongoDB e manipulados usando Mongoose.

2. Configuração do servidor Express

O arquivo principal do backend inicializa o Express, configura o CORS, os middlewares e as diferentes rotas da API.

Criação da aplicação

const express = require("express");
const cors = require("cors");

const app = express();

express permite criar o servidor HTTP, enquanto cors permite a comunicação entre o frontend React e o backend.

3. Importação das rotas

Cada funcionalidade possui seu próprio arquivo de rotas. 

const appointmentRoutes = require("./routes/appointmentRoutes");

4. Configuração do CORS

app.use(
    cors({
        origin: "http://localhost:5173", 
        methods: ["GET", "POST", "PUT", "DELETE", "PATCH"], 
        credentials: true, 
    }) 
);

O frontend funciona aqui na porta 5173.

O middleware CORS permite requisições HTTP provenientes desta origem.

O webhook do Stripe deve ser declarado antes do express.json().

6. Middleware JSON

app.use(express.json()); 
 
app.use( 
    express.urlencoded({ 
        extended: true, 
    }) 
);

express.json() permite que o servidor receba dados no formato JSON.

express.urlencoded() permite processar os dados enviados por meio de formulários.

7. Rotas da API

As principais rotas do backend são organizadas por funcionalidade.

    ```
  • /api/appointments Gerenciamento de agendamentos.
  • /api/batteries Gerenciamento de baterias.
  • /api/contacts Gerenciamento de mensagens de contato.
  • /api/dashboard Gerenciamento dos dados do dashboard.
  • /api/inverters Gerenciamento de inversores.
  • /api/panels Gerenciamento de painéis solares.
  • /api/payments Gerenciamento de pagamentos.
  • /api/quotes Gerenciamento de solicitações de orçamento.
  • /api/reviews Gerenciamento de avaliações dos clientes.
  • /api/users Gerenciamento de autenticação e usuários.
    • ```

8. Modelo Appointment

O modelo Appointment representa um agendamento solicitado por um cliente. 

const appointmentSchema = new mongoose.Schema( 
    { 
        customerName: { 
            type: String, 
            required: true, 
        }, 
 
        email: { 
            type: String, 
            required: true, 
        }, 
 
        phone: { 
            type: String, 
            required: true, 
        }, 
 
        appointmentDate: { 
            type: Date, 
            required: true, 
        }, 
 
        address: { 
            type: String, 
            required: true, 
        }, 
 
        message: { 
            type: String, 
        }, 
 
        status: { 
            type: String, 
            enum: [ 
                "Pending", 
                "Confirmed", 
                "Completed", 
                "Cancelled" 
            ], 
            default: "Pending", 
        }, 
    }, 
    { 
        timestamps: true, 
    } 
); 
 
module.exports = mongoose.model( 
    "Appointment", 
    appointmentSchema 
);

O status permite acompanhar a evolução do agendamento: pendente, confirmado, concluído ou cancelado.

16. Modelo User

O modelo User gerencia as contas de usuários da plataforma. 

const userSchema = new mongoose.Schema( 
    { 
        name: { 
            type: String, 
            required: true, 
            trim: true, 
        }, 
 
        email: { 
            type: String, 
            required: true, 
            unique: true, 
            lowercase: true, 
            trim: true, 
        }, 
 
        password: { 
            type: String, 
            required: true, 
        }, 
 
        phone: { 
            type: String, 
        }, 
 
        role: { 
            type: String, 
            enum: [ 
                "admin", 
                "customer" 
            ], 
            default: "customer", 
        }, 
 
        isVerified: { 
            type: Boolean, 
            default: false, 
        }, 
    }, 
    { 
        timestamps: true, 
    } 
); 
 
module.exports = mongoose.model( 
    "User", 
    userSchema 
);

O campo role diferencia os dois tipos de usuários:

  • admin: acesso às funcionalidades administrativas.
  • customer: acesso às funcionalidades do cliente.

O campo isVerified também permite saber se a conta do usuário foi verificada.

17. Gerenciamento de rotas inexistentes

app.use((req, res) => { 
    res.status(404).json({ 
        success: false, 
        message: `Route introuvable : ${req.method} ${req.originalUrl}`, 
    }); 
});

Quando uma URL da API não existe, o servidor retorna uma resposta HTTP 404.

18. Gerenciamento global de erros

app.use((err, req, res, next) => { 
 
    console.error("❌ Erreur serveur :", err); 
 
    res.status(err.status || 500).json({ 
        success: false, 
        message: err.message || "Erreur interne du serveur", 
    }); 
 
});

Esse middleware permite capturar os erros gerados durante o processamento das requisições.

Em caso de erro interno, o servidor geralmente retorna o código HTTP 500.

19. Conclusão

O backend Solar Energy é organizado em torno de uma arquitetura modular baseada em Node.js, Express e MongoDB.

Os modelos Mongoose permitem estruturar os dados relacionados a usuários, produtos, orçamentos, agendamentos, pagamentos, contatos e avaliações dos clientes.

As diferentes rotas da API permitem que o frontend React se comunique com o backend e execute as operações necessárias para o funcionamento da plataforma.
