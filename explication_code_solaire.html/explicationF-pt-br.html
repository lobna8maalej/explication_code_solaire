☀️ Documentação Frontend — Solar Energy

Explicação dos componentes React, Axios, React Router, autenticação, agendamentos, contatos, avaliações e Dashboard Administrativo.

📚 1. Apresentação geral

Esta parte do projeto corresponde ao Frontend React da plataforma Solar Energy.

Os componentes apresentados permitem que os usuários criem uma conta, façam login, enviem uma mensagem, solicitem um agendamento e consultem as avaliações.

O sistema também possui um Dashboard Administrativo que permite consultar as estatísticas e gerenciar as solicitações de orçamento.

Tecnologias utilizadas:
  • React.js
  • React Hooks (useState, useEffect)
  • Axios para requisições HTTP
  • React Router
  • LocalStorage para o JWT
  • API REST Node.js / Express
  • MongoDB no Backend

⭐ 2. Componente Testimonials.jsx

O componente Testimonials.jsx permite exibir as avaliações dos clientes armazenadas no banco de dados.

2.1 Importação das dependências 

import { useEffect, useState } from "react";
import axios from "axios";
import "./Testimonials.css";

useState permite criar e modificar o estado local do componente.

useEffect permite executar código automaticamente após o carregamento do componente.

axios permite se comunicar com a API Backend.

2.2 Armazenamento das avaliações 

const [reviews, setReviews] = useState([]);

Inicialmente, a lista de avaliações está vazia. A função setReviews permite posteriormente atualizar essa lista.

2.3 Recuperação das avaliações 

useEffect(() => {

    axios
        .get("http://localhost:3000/api/reviews")

        .then((res) => {

            console.log(
                "API REVIEWS :",
                res.data
            );

        })

        .catch((error) => {

            console.log(
                "Erreur API :",
                error
            );

        });

}, []);

Quando a página é carregada, uma requisição GET é enviada para: 

GET /api/reviews

O Backend retorna as avaliações disponíveis.

2.4 Filtragem das avaliações aprovadas 

res.data.data.filter(
    review => review.status === "Approved"
)

O componente exibe apenas as avaliações cujo status é Approved.

Por quê?

As avaliações podem ser criadas pelos clientes, mas precisam ser aprovadas pelo administrador antes de serem exibidas publicamente.

2.5 Exibição das estrelas 

{"⭐".repeat(review.rating)}

Se a avaliação for 5, o React gera:

⭐⭐⭐⭐⭐

2.6 Exibição da avaliação 

{reviews.map(review => (

    <div
        className="review-card"
        key={review._id}
    >

        <h3>
            {review.customerName}
        </h3>

        <p>
            {"⭐".repeat(review.rating)}
        </p>

        <p>
            {review.comment}
        </p>

        <strong>
            {review.productName}
        </strong>

    </div>

))}

map() percorre todas as avaliações e cria um cartão HTML para cada avaliação.

📅 4. Componente Appointment.jsx

O componente Appointment permite ao cliente solicitar um agendamento com a Solar Energy.

4.1 Estado do formulário 

const [form, setForm] = useState({

    customerName: "",
    email: "",
    phone: "",
    appointmentDate: "",
    address: "",
    message: "",

});

O objeto form contém todas as informações inseridas pelo cliente.

4.2 Estado de carregamento 

const [loading, setLoading] = useState(false);

Essa variável permite saber se a requisição está em andamento.

4.3 Alteração do formulário 

const handleChange = (e) => {

    const { name, value } = e.target;

    setForm((prev) => ({
        ...prev,
        [name]: value,
    }));

};

Essa função recupera o nome do campo e seu valor.

Por exemplo, se o usuário escrever Ahmed no campo customerName, o React atualiza: 

form.customerName = "Ahmed"

4.4 Envio do agendamento 

const response = await axios.post(
    "http://localhost:3000/api/appointments",
    {
        customerName: form.customerName,
        email: form.email,
        phone: form.phone,
        appointmentDate: form.appointmentDate,
        address: form.address,
        message: form.message,
    }
);

Ao enviar o formulário, o Axios realiza uma requisição POST para: 

POST /api/appointments

4.5 Redefinição do formulário 

setForm({
    customerName: "",
    email: "",
    phone: "",
    appointmentDate: "",
    address: "",
    message: "",
});

Após um envio bem-sucedido, todos os campos são limpos.

4.6 Navegação 

navigate("/quote");

Após a criação do agendamento, o usuário é redirecionado para a página /quote.

4.7 Data mínima 

min={
    new Date()
        .toISOString()
        .split("T")[0]
}

Essa instrução impede o usuário de selecionar uma data no passado.

4.8 Botão dinâmico 

{loading
    ? "⏳ Envoi en cours..."
    : "📅 Demander un rendez-vous"}

Durante o envio, o botão indica que a requisição está em andamento e fica desativado.

🔐 5. Componente Auth.jsx

O componente Auth gerencia tanto o cadastro quanto o login dos usuários.

5.1 Modo login / cadastro 

const [mode, setMode] = useState("login");

O modo inicial é login.

Quando o modo é register, o formulário também exibe o campo Nome.

5.2 Dados do formulário 

const [form, setForm] = useState({

    name: "",
    email: "",
    password: "",

});

5.3 Login 

const response = await axios.post(
    "http://localhost:3000/api/users/login",
    {
        email: form.email,
        password: form.password,
    }
);

Uma requisição POST é enviada ao Backend para verificar o endereço de email e a senha.

5.4 Recuperação do JWT 

if (response.data.token) {

    localStorage.setItem(
        "token",
        response.data.token
    );

}

Se o login for realizado com sucesso, o Backend retorna um JWT.

O token é então armazenado no localStorage.

Fluxo de autenticação:
Usuário → Login → Backend → Verificação → JWT → localStorage

5.5 Redirecionamento após o login 

navigate("/products");

Após um login bem-sucedido, o usuário é redirecionado para a página de produtos.

5.6 Cadastro 

await axios.post(
    "http://localhost:3000/api/users/register",
    {
        name: form.name,
        email: form.email,
        password: form.password,
    }
);

O formulário de cadastro envia o nome, o email e a senha para o Backend.

5.7 Retorno ao login 

setMode("login");

Após a criação da conta, o formulário retorna automaticamente ao modo de login.

5.8 Alteração Login / Register 

setMode(
    mode === "login"
        ? "register"
        : "login"
);

Essa lógica permite que o usuário alterne entre login e cadastro.

📊 7. Dashboard.jsx

O componente Dashboard representa o painel administrativo da Solar Energy.

Ele permite consultar as estatísticas gerais e as solicitações de orçamento.

7.1 Estado das estatísticas 

const [stats, setStats] = useState({

    users: 0,
    panels: 0,
    batteries: 0,
    inverters: 0,
    appointments: 0,
    quotes: 0,
    payments: 0,
    contacts: 0,
    reviews: 0,

});

O Dashboard possui vários indicadores:

  • 👥 Usuários
  • ☀️ Painéis
  • 🔋 Baterias
  • ⚡ Inversores
  • 📅 Agendamentos
  • 📄 Solicitações de orçamento
  • 💳 Pagamentos
  • 📩 Contatos
  • ⭐ Avaliações

7.2 Carregamento inicial 

useEffect(() => {

    fetchDashboard();

    fetchQuotes();

}, []);

Ao carregar o Dashboard, duas funções são executadas:

  • fetchDashboard() para as estatísticas
  • fetchQuotes() para os orçamentos

7.3 Recuperação do token 

const token =
    localStorage.getItem("token");

O token JWT armazenado durante o login é recuperado do localStorage.

7.4 Autenticação da requisição 

headers: {

    Authorization:
        `Bearer ${token}`,

}

O token é enviado no cabeçalho HTTP Authorization.

Importante:

O Backend pode assim verificar se a requisição vem de um usuário autenticado.

7.5 API do Dashboard 

axios.get(
    "http://localhost:3000/api/dashboard",
    {
        headers: {
            Authorization:
                `Bearer ${token}`,
        },
    }
);

7.6 Processamento da resposta 

if (
    response.data &&
    response.data.success &&
    response.data.data
) {

    const data =
        response.data.data;

    setStats({

        users: data.users || 0,

        panels: data.panels || 0,

        batteries:
            data.batteries || 0,

        inverters:
            data.inverters || 0,

        appointments:
            data.appointments || 0,

        quotes:
            data.quotes || 0,

        payments:
            data.payments || 0,

        contacts:
            data.contacts || 0,

        reviews:
            data.reviews || 0,

    });

}

7.7 Recuperação dos orçamentos

A função fetchQuotes() recupera as solicitações de orçamento. 

const response = await axios.get(
    "http://localhost:3000/api/quotes",
    {
        headers: {
            Authorization:
                `Bearer ${token}`,
        },
    }
);

7.8 Gerenciamento de vários formatos de API

O código aceita vários formatos de resposta: 

// Formato 1
[ {...}, {...} ]

// Formato 2
{ data: [...] }

// Formato 3
{ quotes: [...] }

// Formato 4
{ data: { quotes: [...] } }

Essa lógica torna o componente mais flexível quando a estrutura da resposta do Backend muda.

7.9 Alteração do status de um orçamento 

const updateQuoteStatus =
    async (id, status) => {

    const response =
        await axios.put(
            `http://localhost:3000/api/quotes/${id}`,
            {
                status: status,
            },
            {
                headers: {
                    Authorization:
                        `Bearer ${token}`,
                },
            }
        );

};

O administrador pode alterar o status de um orçamento.

7.10 Status disponíveis

  • Pending — Pendente
  • Reviewed — Solicitação analisada
  • Approved — Aprovada
  • Rejected — Rejeitada

7.11 Lógica das ações

Pending

👁️ Consultar → Reviewed

✅ Aceitar → Approved

❌ Recusar → Rejected

Reviewed

✅ Aceitar → Approved

❌ Recusar → Rejected

Approved:

O Dashboard indica que o orçamento foi aprovado e que o cliente agora pode realizar o pagamento.

Rejected:

O Dashboard informa que o orçamento foi rejeitado.

📩 8. DashboardContacts.jsx

O componente DashboardContacts permite que o administrador consulte as mensagens enviadas pelo formulário Contact.

8.1 Estado dos contatos 

const [contacts, setContacts] =
    useState([]);

const [loading, setLoading] =
    useState(true);

8.2 Carregamento automático 

useEffect(() => {

    fetchContacts();

}, []);

Assim que a página é carregada, fetchContacts() é executada.

8.3 Verificação do token 

const token =
    localStorage.getItem("token");

if (!token) {

    setContacts([]);

    setLoading(false);

    return;

}

O acesso às mensagens requer um token de autenticação.

8.4 Requisição à API 

const res = await axios.get(
    "http://localhost:3000/api/contacts",
    {
        headers: {
            Authorization:
                `Bearer ${token}`,
        },
    }
);

O componente chama: 

GET /api/contacts

8.5 Extração dos contatos

Assim como nos orçamentos, vários formatos de resposta são suportados. 

// Formato 1
[ {...}, {...} ]

// Formato 2
{ data: [...] }

// Formato 3
{ contacts: [...] }

// Formato 4
{ data: { contacts: [...] } }

8.6 Contador de mensagens 

{contacts.length}

contacts.length indica o número total de mensagens recuperadas.

Exemplo: 

5 mensagens

8.7 Exibição das informações

Cada mensagem é exibida em um cartão. 

{contacts.map((contact) => (

    <div
        className="contact-card"
        key={contact._id}
    >

        ...

    </div>

))}

8.8 Informações exibidas

  • 👤 Nome do cliente
  • 📧 Email
  • 📱 Telefone
  • 📌 Assunto
  • 💬 Mensagem
  • 📊 Status
  • 📅 Data

8.9 Gerenciamento do nome 

contact.fullName ||
contact.name ||
"Client"

O componente tenta primeiro utilizar fullName. Se essa propriedade não existir, utiliza name. Caso contrário, exibe Client.

8.10 Gerenciamento de um erro 401 

if (
    error.response?.status === 401
) {

    alert(
        "Session expirée. Veuillez vous reconnecter."
    );

    localStorage.removeItem(
        "token"
    );

    window.location.href =
        "/auth";
}

O código verifica se o Backend retorna o status HTTP 401.

Isso geralmente significa que o token está ausente, inválido ou expirado.

Nesse caso:

  1. Uma mensagem é exibida.
  2. O token é removido.
  3. O usuário é redirecionado para /auth.

🔄 9. Funcionamento geral do Frontend

Os diferentes componentes se comunicam com o Backend por meio de APIs REST.

👤 Usuário

↓

React

↓

Axios

↓

API Express

↓

MongoDB

Principais APIs utilizadas

  • POST /api/users/register — cadastro
  • POST /api/users/login — login
  • GET /api/reviews — recuperação das avaliações
  • POST /api/appointments — criação de um agendamento
  • POST /api/contacts — criação de uma mensagem
  • GET /api/dashboard — estatísticas do administrador
  • GET /api/quotes — recuperação dos orçamentos
  • PUT /api/quotes/:id — alteração do status de um orçamento
  • GET /api/contacts — recuperação das mensagens

🔑 10. Autenticação JWT

O sistema utiliza um token JWT para proteger determinadas rotas administrativas.

1. O usuário faz login.

↓

2. O Backend verifica suas credenciais.

↓

3. O Backend gera um JWT.

↓

4. O React armazena o JWT no localStorage.

↓

5. O Axios envia o JWT com as requisições protegidas.

↓

6. O Middleware do Backend verifica o token. 

Authorization: Bearer TOKEN
