# 1 — Arquitectura general del Backend

El backend constituye la parte del servidor de la aplicación Solar Energy.

Permite que el frontend React se comunique con la base de datos MongoDB mediante una API REST desarrollada con Node.js y Express.

Tecnologías utilizadas

  • Node.js: entorno de ejecución de JavaScript del lado del servidor.
  • Express: framework que permite crear la API REST.
  • MongoDB: base de datos NoSQL.
  • Mongoose: biblioteca que permite manipular MongoDB.
  • JWT: sistema utilizado para la autenticación.
  • bcryptjs: biblioteca utilizada para proteger las contraseñas.
  • Multer: middleware que permite gestionar archivos.
Arquitectura:

React Frontend → Axios → Express API → Controllers → Models Mongoose → MongoDB

# 3 — Middleware de autenticación JWT

El middleware verifyToken permite comprobar si el usuario posee un token JWT válido. 

const jwt = 
    require("jsonwebtoken"); 
 
const verifyToken = 
    (req, res, next) => { 
 
    try { 
 
        console.log( 
            "Authorization :", 
            req.headers.authorization 
        ); 
 
        const token = 
            req.headers.authorization 
                ?.split(" ")[1]; 
 
        if (!token) { 
 
            return res.status(401).json({ 
 
                success: false, 
 
                message: 
                    "Accès refusé, token manquant", 
 
            }); 
 
        } 
 
        const decoded = 
            jwt.verify( 
                token, 
                process.env.JWT_SECRET 
            ); 
 
        req.user = decoded; 
 
        next(); 
 
    } catch (error) { 
 
        return res.status(401).json({ 
 
            success: false, 
 
            message: 
                "Token invalide", 
 
        }); 
 
    } 
 
}; 
 
module.exports = { 
    verifyToken 
};

Funcionamiento

  1. El frontend envía el token en el header Authorization.
  2. El middleware recupera el token.
  3. JWT verifica el token utilizando JWT_SECRET.
  4. La información decodificada se almacena en req.user.
  5. next() autoriza el acceso a la ruta.
Resultado:

Las rutas protegidas pueden verificar la identidad del usuario mediante req.user.

# 15 — Flujo completo de una solicitud

Cuando un usuario utiliza la aplicación, varios componentes se comunican entre sí.

Ejemplo: solicitar una cotización

  1. El cliente completa el formulario React.
  2. React utiliza Axios para enviar los datos.
  3. La solicitud llega a Express.
  4. Express dirige la solicitud a la ruta de cotizaciones.
  5. El controlador recibe los datos.
  6. Mongoose crea el documento en MongoDB.
  7. Se envía un correo electrónico de confirmación al cliente.
  8. El backend devuelve una respuesta JSON.
  9. React muestra el resultado al usuario.
Flujo:

Cliente → React → Axios → Express → Ruta → Controlador → Mongoose → MongoDB

Luego:

MongoDB → Controlador → JSON → Axios → React → Cliente

# 16 — Conclusión

El backend de Solar Energy está organizado según una arquitectura modular.

Cada funcionalidad tiene su propio modelo, su controlador y sus rutas.

  • Los Models definen la estructura de los datos de MongoDB.
  • Los Controllers contienen la lógica de negocio.
  • Las Routes definen los endpoints de la API.
  • Los Middleware controlan determinadas solicitudes, especialmente la autenticación.
  • JWT protege el acceso a las funcionalidades protegidas.
  • bcrypt protege las contraseñas.
  • MongoDB + Mongoose garantizan la gestión de los datos.
  • Stripe permite gestionar los pagos.
  • Los correos electrónicos permiten confirmar las acciones realizadas por los clientes.
Arquitectura final:

Frontend React → Axios → API Express → Routes → Controllers → Mongoose → MongoDB
