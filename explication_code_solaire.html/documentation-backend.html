# 1 — Architecture générale du Backend

Le backend constitue la partie serveur de l'application Solar Energy.

Il permet au frontend React de communiquer avec la base de données MongoDB grâce à une API REST développée avec Node.js et Express.

Technologies utilisées

  • Node.js : environnement d'exécution JavaScript côté serveur.
  • Express : framework permettant de créer l'API REST.
  • MongoDB : base de données NoSQL.
  • Mongoose : bibliothèque permettant de manipuler MongoDB.
  • JWT : système utilisé pour l'authentification.
  • bcryptjs : bibliothèque utilisée pour sécuriser les mots de passe.
  • Multer : middleware permettant de gérer les fichiers.
Architecture :

React Frontend → Axios → Express API → Controllers → Models Mongoose → MongoDB

# 3 — Middleware d'authentification JWT

Le middleware verifyToken permet de vérifier si l'utilisateur possède un token JWT valide. 

const jwt =
    require("jsonwebtoken");

const verifyToken =
    (req, res, next) => {

    try {

        console.log(
            "Authorization :",
            req.headers.authorization
        );

        const token =
            req.headers.authorization
                ?.split(" ")[1];

        if (!token) {

            return res.status(401).json({

                success: false,

                message:
                    "Accès refusé, token manquant",

            });

        }

        const decoded =
            jwt.verify(
                token,
                process.env.JWT_SECRET
            );

        req.user = decoded;

        next();

    } catch (error) {

        return res.status(401).json({

            success: false,

            message:
                "Token invalide",

        });

    }

};

module.exports = {
    verifyToken
};

Fonctionnement

  1. Le frontend envoie le token dans le header Authorization.
  2. Le middleware récupère le token.
  3. JWT vérifie le token avec JWT_SECRET.
  4. Les informations décodées sont stockées dans req.user.
  5. next() autorise l'accès à la route.
Résultat :

Les routes protégées peuvent vérifier l'identité de l'utilisateur grâce à req.user.

# 4 — Gestion des fichiers avec Multer 

const multer =
    require("multer");

const storage =
    multer.memoryStorage();

const upload =
    multer({

        storage,

        limits: {

            fileSize:
                5 * 1024 * 1024,

        },

    });

module.exports = upload;

Multer permet de recevoir des fichiers envoyés depuis le frontend.

memoryStorage() conserve temporairement le fichier en mémoire.

La taille maximale autorisée est de 5 MB.

# 5 — Controller des panneaux solaires

Importation du modèle 

const Panel =
    require("../models/Panel");

Le controller utilise le modèle Panel pour communiquer avec MongoDB.

Créer un panneau 

exports.createPanel =
async (req, res) => {

    try {

        const panel =
            await Panel.create(req.body);

        res.status(201).json({

            success: true,

            data: panel,

        });

    } catch (error) {

        res.status(400).json({

            success: false,

            message: error.message,

        });

    }

};

req.body contient les informations du panneau envoyées par le frontend.

Récupérer tous les panneaux 

exports.getPanels =
async (req, res) => {

    try {

        const panels =
            await Panel.find();

        res.json(panels);

    } catch (error) {

        res.status(500).json({

            message:
                error.message

        });

    }

};

Récupérer un panneau par ID 

const panel =
    await Panel.findById(
        req.params.id
    );

req.params.id correspond à l'identifiant présent dans l'URL.

Modifier un panneau 

const panel =
    await Panel.findByIdAndUpdate(

        req.params.id,

        req.body,

        {
            new: true,
            runValidators: true
        }

    );

new: true permet de retourner le panneau après modification.

runValidators: true permet de respecter les règles définies dans le modèle Mongoose.

Supprimer un panneau 

const panel =
    await Panel.findByIdAndDelete(
        req.params.id
    );

Le panneau correspondant à l'ID est supprimé de MongoDB.

# 12 — Authentification et gestion des utilisateurs

Création d'un compte 

const hashedPassword =
    await bcrypt.hash(
        password,
        10
    );

Le mot de passe n'est pas enregistré directement. Il est transformé en hash grâce à bcrypt.

Création de l'utilisateur 

const user =
    await User.create({

        name,

        email,

        password:
            hashedPassword,

        phone,

        role: "client"

    });
Attention :

Dans ton modèle User fourni précédemment, les rôles autorisés sont admin et customer.

Ton controller utilise actuellement role: "client".

Il faut donc harmoniser ces valeurs.

Connexion 

const user =
    await User.findOne({
        email
    });

Le serveur recherche l'utilisateur correspondant à l'adresse e-mail.

Vérification du mot de passe 

const isMatch =
    await bcrypt.compare(

        password,

        user.password

    );

Génération du token JWT 

const token =
    jwt.sign(

        {
            id: user._id,
            role: user.role
        },

        process.env.JWT_SECRET,

        {
            expiresIn: "7d"
        }

    );

Le token contient l'identifiant de l'utilisateur et son rôle.

Le token expire après 7 jours.

Changer le mot de passe 

const hashedPassword =
    await bcrypt.hash(
        password,
        10
    );

user.password =
    hashedPassword;

await user.save();

Récupérer les utilisateurs 

const users =
    await User.find()

        .select("-password")

        .sort({
            createdAt: -1
        });

.select("-password") empêche le serveur de retourner le mot de passe dans la réponse.

Supprimer un utilisateur 

await User.findByIdAndDelete(
    req.params.id
);

# 15 — Flux complet d'une requête

Lorsqu'un utilisateur utilise l'application, plusieurs composants communiquent entre eux.

Exemple : demander un devis

  1. Le client remplit le formulaire React.
  2. React utilise Axios pour envoyer les données.
  3. La requête arrive sur Express.
  4. Express dirige la requête vers la route des devis.
  5. Le controller reçoit les données.
  6. Mongoose crée le document dans MongoDB.
  7. Un e-mail de confirmation est envoyé au client.
  8. Le backend retourne une réponse JSON.
  9. React affiche le résultat à l'utilisateur.
Flux :

Client → React → Axios → Express → Route → Controller → Mongoose → MongoDB

Puis :

MongoDB → Controller → JSON → Axios → React → Client

# 16 — Conclusion

Le backend Solar Energy est organisé selon une architecture modulaire.

Chaque fonctionnalité possède son propre modèle, son controller et ses routes.

  • Les Models définissent la structure des données MongoDB.
  • Les Controllers contiennent la logique métier.
  • Les Routes définissent les endpoints de l'API.
  • Les Middleware contrôlent certaines requêtes, notamment l'authentification.
  • JWT sécurise l'accès aux fonctionnalités protégées.
  • bcrypt protège les mots de passe.
  • MongoDB + Mongoose assurent la gestion des données.
  • Stripe permet de gérer les paiements.
  • Les e-mails permettent de confirmer les actions effectuées par les clients.
Architecture finale :

Frontend React → Axios → API Express → Routes → Controllers → Mongoose → MongoDB
