# 17 — Routes de l'API Backend

Les fichiers présents dans le dossier routes définissent les différentes URL de l'API Backend Solar Energy.

Chaque route reçoit une requête HTTP provenant du frontend React et la transmet au controller correspondant.

Structure générale d'une route 

const express = require("express");

const router = express.Router();

router.get("/", controller);

module.exports = router;
  • express importe le framework Express.
  • express.Router() permet de créer un routeur indépendant.
  • Les méthodes GET, POST, PUT et DELETE définissent les opérations de l'API.
  • Le controller contient la logique exécutée lorsque la route est appelée.
  • module.exports permet d'utiliser le routeur dans app.js.

# 18 — Routes des rendez-vous

Le fichier appointmentRoutes.js permet de gérer les rendez-vous clients. 

const express = require("express");

const router = express.Router();

const {
    createAppointment,
    getAppointments,
    getAppointmentById,
    updateAppointment,
    deleteAppointment,
} = require("../controllers/appointmentController");

Les fonctions du controller sont importées afin d'être utilisées par les différentes routes.

Créer un rendez-vous 

router.post(
    "/",
    createAppointment
);

Cette route utilise la méthode POST pour créer un nouveau rendez-vous.

Récupérer tous les rendez-vous 

router.get(
    "/",
    getAppointments
);

Cette route retourne la liste des rendez-vous enregistrés dans MongoDB.

Récupérer un rendez-vous par ID 

router.get(
    "/:id",
    getAppointmentById
);

:id représente l'identifiant du rendez-vous présent dans l'URL.

Modifier un rendez-vous 

router.put(
    "/:id",
    updateAppointment
);

Cette route permet de modifier un rendez-vous existant.

Supprimer un rendez-vous 

router.delete(
    "/:id",
    deleteAppointment
);

Cette route supprime le rendez-vous correspondant à l'identifiant fourni.

URL principale : /api/appointments

Les opérations disponibles sont :

POST → créer
GET → récupérer
PUT → modifier
DELETE → supprimer

# 19 — Routes d'authentification et utilisateurs

Le fichier authRoutes.js permet de gérer l'inscription, la connexion et les opérations concernant les utilisateurs. 

const {
    register,
    login,
    updateUser,
    changePassword,
    getUsers,
    deleteUser
} = require("../controllers/authController");

Les fonctions du controller d'authentification sont importées depuis authController.js.

Créer un compte 

router.post(
    "/register",
    register
);

Cette route permet à un nouvel utilisateur de créer un compte.

Connexion 

router.post(
    "/login",
    login
);

Cette route permet à l'utilisateur de se connecter. Le controller vérifie les informations de connexion et peut générer un token JWT.

Récupérer les utilisateurs 

router.get(
    "/users",
    getUsers
);

Cette route récupère la liste des utilisateurs.

Modifier un utilisateur 

router.put(
    "/:id",
    updateUser
);

Cette route permet de modifier les informations d'un utilisateur identifié par son ID.

Changer le mot de passe 

router.put(
    "/:id/password",
    changePassword
);

Cette route permet de modifier le mot de passe d'un utilisateur.

Supprimer un utilisateur 

router.delete(
    "/:id",
    deleteUser
);

Cette route supprime l'utilisateur correspondant à l'ID.

Exemples d'URL :

/api/users/register
/api/users/login
/api/users/users
/api/users/:id
/api/users/:id/password

Envoyer un message 

router.post(
    "/",

router.get(

    updatePayment,
    deletePayment,
} = require("../controllers/paymentController");

Créer un paiement normal

    "/",
    createPayment
);

Cette route permet d'enregistrer un paiement classique.

Créer une session Stripe Checkout 

router.post(
    "/stripe-checkout",
    createStripeCheckout
);

Cette route permet de demander au backend de créer une session de paiement Stripe.

Important :

La route /stripe-checkout est déclarée avant /:id.

Cela permet à Express d'interpréter correctement stripe-checkout comme une route spécifique et non comme une valeur du paramètre :id.

# 28 — Résumé de l'API Backend

L'ensemble des fichiers de routes permet de structurer l'API Solar Energy en plusieurs fonctionnalités indépendantes.

Fonctionnalité URL principale Opérations
Rendez-vous /api/appointments POST, GET, PUT, DELETE
Utilisateurs /api/users POST, GET, PUT, DELETE
Batteries /api/batteries POST, GET, PUT, DELETE
Contacts /api/contacts POST, GET, PUT, DELETE
Dashboard /api/dashboard GET
Onduleurs /api/inverters POST, GET, PUT, DELETE
Panneaux /api/panels POST, GET, PUT, DELETE
Paiements /api/payments POST, GET, PUT, DELETE
Devis /api/quotes POST, GET, PUT, DELETE
Avis /api/reviews POST, GET, PUT, DELETE

Architecture des routes

Flux général :

React → Axios → Express → Route → Middleware → Controller → Model Mongoose → MongoDB

Puis la réponse revient vers le frontend :

MongoDB → Controller → JSON → Axios → React

Rôle des différents éléments

  • Routes : définissent les URL et les méthodes HTTP.
  • Middleware : vérifie certaines conditions avant l'exécution du controller.
  • Controllers : contiennent la logique métier.
  • Models : permettent de communiquer avec MongoDB grâce à Mongoose.
  • MongoDB : stocke les données de l'application.
Résultat :

L'utilisation de plusieurs fichiers de routes permet de garder un backend organisé, modulaire et plus facile à maintenir.
