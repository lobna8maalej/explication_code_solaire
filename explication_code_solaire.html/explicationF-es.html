☀️ Documentación Frontend — Solar Energy

Explicación de los componentes React, Axios, React Router, autenticación, citas, contactos, reseñas y Dashboard de Administración.

📚 1. Presentación general

Esta parte del proyecto corresponde al Frontend React de la plataforma Solar Energy.

Los componentes presentados permiten a los usuarios crear una cuenta, iniciar sesión, enviar un mensaje, solicitar una cita y consultar las reseñas.

El sistema también cuenta con un Dashboard de Administración que permite consultar las estadísticas y gestionar las solicitudes de presupuesto.

Tecnologías utilizadas:
  • React.js
  • React Hooks (useState, useEffect)
  • Axios para las solicitudes HTTP
  • React Router
  • LocalStorage para el JWT
  • API REST Node.js / Express
  • MongoDB en el Backend

⭐ 2. Componente Testimonials.jsx

El componente Testimonials.jsx permite mostrar las reseñas de los clientes almacenadas en la base de datos.

2.1 Importación de dependencias 

import { useEffect, useState } from "react";
import axios from "axios";
import "./Testimonials.css";

useState permite crear y modificar el estado local del componente.

useEffect permite ejecutar código automáticamente después de cargar el componente.

axios permite comunicarse con la API Backend.

2.2 Almacenamiento de reseñas 

const [reviews, setReviews] = useState([]);

Al principio, la lista de reseñas está vacía. La función setReviews permite posteriormente actualizar esta lista.

2.3 Recuperación de las reseñas 

useEffect(() => {

    axios
        .get("http://localhost:3000/api/reviews")

        .then((res) => {

            console.log(
                "API REVIEWS :",
                res.data
            );

        })

        .catch((error) => {

            console.log(
                "Erreur API :",
                error
            );

        });

}, []);

Cuando se carga la página, se envía una solicitud GET a: 

GET /api/reviews

El Backend devuelve las reseñas disponibles.

2.4 Filtrado de las reseñas aprobadas 

res.data.data.filter(
    review => review.status === "Approved"
)

El componente solo muestra las reseñas cuyo estado es Approved.

¿Por qué?

Los clientes pueden crear reseñas, pero deben ser validadas por el administrador antes de mostrarse públicamente.

2.5 Visualización de las estrellas 

{"⭐".repeat(review.rating)}

Si la puntuación es 5, React genera:

⭐⭐⭐⭐⭐

2.6 Visualización de la reseña 

{reviews.map(review => (

    <div
        className="review-card"
        key={review._id}
    >

        <h3>
            {review.customerName}
        </h3>

        <p>
            {"⭐".repeat(review.rating)}
        </p>

        <p>
            {review.comment}
        </p>

        <strong>
            {review.productName}
        </strong>

    </div>

map() recorre todas las reseñas y crea una tarjeta HTML para cada reseña.

📅 4. Componente Appointment.jsx

El componente Appointment permite al cliente solicitar una cita con Solar Energy.

4.1 Estado del formulario 

const [form, setForm] = useState({

    customerName: "",
    email: "",
    phone: "",
    appointmentDate: "",
    address: "",
    message: "",

});

El objeto form contiene toda la información introducida por el cliente.

4.2 Estado de carga 

const [loading, setLoading] = useState(false);

Esta variable permite saber si la solicitud está actualmente en curso.

4.3 Modificación del formulario 

const handleChange = (e) => {

    const { name, value } = e.target;

    setForm((prev) => ({
        ...prev,
        [name]: value,
    }));

};

Esta función obtiene el nombre del campo y su valor.

Por ejemplo, si el usuario escribe Ahmed en el campo customerName, React actualiza: 

form.customerName = "Ahmed"

4.4 Envío de la cita 

const response = await axios.post(
    "http://localhost:3000/api/appointments",
    {
        customerName: form.customerName,
        email: form.email,
        phone: form.phone,
        appointmentDate: form.appointmentDate,
        address: form.address,
        message: form.message,
    }
);

Al enviar el formulario, Axios realiza una solicitud POST a: 

POST /api/appointments

4.5 Restablecimiento del formulario 

setForm({
    customerName: "",
    email: "",
    phone: "",
    appointmentDate: "",
    address: "",
    message: "",
});

Después de un envío exitoso, todos los campos se vacían.

4.6 Navegación 

navigate("/quote");

Después de crear la cita, el usuario es redirigido a la página /quote.

4.7 Fecha mínima 

min={
    new Date()
        .toISOString()
        .split("T")[0]
}

Esta instrucción impide al usuario seleccionar una fecha del pasado.

4.8 Botón dinámico 

{loading
    ? "⏳ Envoi en cours..."
    : "📅 Demander un rendez-vous"}

Durante el envío, el botón indica que la solicitud está en curso y se desactiva.

🔐 5. Componente Auth.jsx

El componente Auth gestiona tanto el registro como el inicio de sesión de los usuarios.

5.1 Modo inicio de sesión / registro 

const [mode, setMode] = useState("login");

El modo inicial es login.

Cuando el modo es register, el formulario también muestra el campo Nombre.

5.2 Datos del formulario 

const [form, setForm] = useState({

    name: "",
    email: "",
    password: "",

});

5.3 Inicio de sesión 

const response = await axios.post(
    "http://localhost:3000/api/users/login",
    {
        email: form.email,
        password: form.password,
    }
);

Se envía una solicitud POST al Backend para verificar la dirección de email y la contraseña.

5.4 Recuperación del JWT 

if (response.data.token) {

    localStorage.setItem(
        "token",
        response.data.token
    );

}

Si el inicio de sesión es correcto, el Backend devuelve un JWT.

El token se guarda posteriormente en localStorage.

Flujo de autenticación:
Usuario → Login → Backend → Verificación → JWT → localStorage

5.5 Redirección después del inicio de sesión 

navigate("/products");

Después de iniciar sesión correctamente, el usuario es redirigido a la página de productos.

5.6 Registro 

await axios.post(
    "http://localhost:3000/api/users/register",
    {
        name: form.name,
        email: form.email,
        password: form.password,
    }
);

El formulario de registro envía el nombre, el email y la contraseña al Backend.

5.7 Volver al inicio de sesión 

setMode("login");

Después de crear la cuenta, el formulario vuelve automáticamente al modo de inicio de sesión.

5.8 Cambio Login / Register 

setMode(
    mode === "login"
        ? "register"
        : "login"
);

Esta lógica permite al usuario cambiar entre inicio de sesión y registro.

const [stats, setStats] = useState({

El Dashboard contiene varios indicadores:

  • 👥 Usuarios
  • ☀️ Paneles
  • 🔋 Baterías
  • ⚡ Inversores
  • 📅 Citas
  • 📄 Solicitudes de presupuesto
  • 💳 Pagos
  • 📩 Contactos
  • ⭐ Reseñas

7.2 Carga inicial 

useEffect(() => {

    fetchDashboard();

    fetchQuotes();

}, []);

Al cargar el Dashboard, se ejecutan dos funciones:

  • fetchDashboard() para las estadísticas
  • fetchQuotes() para los presupuestos

7.3 Recuperación del token 

const token =

headers: {

        `Bearer ${token}`,

El token se envía en la cabecera HTTP Authorization.

Importante:

El Backend puede así verificar que la solicitud proviene de un usuario autenticado.

7.5 API del Dashboard 

axios.get(

7.8 Gestión de varios formatos de API

El código admite varios formatos de respuesta:

// Formato 2

// Formato 3
{ quotes: [...] }

// Formato 4

Esta lógica hace que el componente sea más flexible cuando cambia la estructura de la respuesta del Backend.

7.9 Modificación del estado de un presupuesto 

const updateQuoteStatus =
    async (id, status) => {

    const response =
        await axios.put(
            `http://localhost:3000/api/quotes/${id}`,
            {
                status: status,
            },
            {
                headers: {
                    Authorization:
                        `Bearer ${token}`,
                },
            }
        );

};

El administrador puede modificar el estado de un presupuesto.

7.10 Estados disponibles

  • Pending — Pendiente
  • Reviewed — Solicitud consultada
  • Approved — Aprobada
  • Rejected — Rechazada

7.11 Lógica de las acciones

Pending

👁️ Consultar → Reviewed

✅ Aceptar → Approved

❌ Rechazar → Rejected

Reviewed

✅ Aceptar → Approved

❌ Rechazar → Rejected

Approved:

El Dashboard indica que el presupuesto ha sido aprobado y que el cliente ahora puede realizar el pago.

Rejected:

El Dashboard muestra que el presupuesto ha sido rechazado.

8.10 Gestión de un error 401 

if (
    error.response?.status === 401
) {

    alert(
        "Session expirée. Veuillez vous reconnecter."
    );

    localStorage.removeItem(
        "token"
    );

    window.location.href =
        "/auth";
}

El código comprueba si el Backend devuelve el estado HTTP 401.

Esto generalmente significa que el token está ausente, es inválido o ha expirado.

En este caso:

  1. Se muestra un mensaje.
  2. Se elimina el token.
  3. El usuario es redirigido a /auth.

🔄 9. Funcionamiento general del Frontend

Los diferentes componentes se comunican con el Backend mediante API REST.

👤 Usuario

↓

React

↓

Axios

↓

API Express

↓

MongoDB

Principales API utilizadas

  • POST /api/users/register — registro
  • POST /api/users/login — inicio de sesión
  • GET /api/reviews — recuperar reseñas
  • POST /api/appointments — crear una cita
  • POST /api/contacts — crear un mensaje
  • GET /api/dashboard — estadísticas del administrador
  • GET /api/quotes — recuperar presupuestos
  • PUT /api/quotes/:id — modificar el estado de un presupuesto
  • GET /api/contacts — recuperar mensajes

🔑 10. Autenticación JWT

El sistema utiliza un token JWT para proteger determinadas rutas de administración.

1. El usuario inicia sesión.

↓

2. El Backend verifica sus credenciales.

↓

3. El Backend genera un JWT.

↓

4. React almacena el JWT en localStorage.

↓

5. Axios envía el JWT con las solicitudes protegidas.

↓

6. El Middleware del Backend verifica el token. 

Authorization: Bearer TOKEN
