1. Présentation du Backend

Le backend de la plateforme Solar Energy est développé avec Node.js et Express.js.

Il permet de gérer les utilisateurs, les produits solaires, les demandes de devis, les rendez-vous, les contacts, les paiements et les avis clients.

Les données sont stockées dans une base de données MongoDB et manipulées avec Mongoose.

```
```

2. Configuration du serveur Express

Le fichier principal du backend initialise Express, configure CORS, les middlewares et les différentes routes API.

Création de l'application

``` 
const express = require("express");
const cors = require("cors");

const app = express();
```

express permet de créer le serveur HTTP tandis que cors autorise les communications entre le frontend React et le backend.

```
```

4. Configuration CORS

``` 
app.use(
    cors({
        origin: "http://localhost:5173",
        methods: ["GET", "POST", "PUT", "DELETE", "PATCH"],
        credentials: true,
    })
);
```

Le frontend fonctionne ici sur le port 5173.

Le middleware CORS autorise les requêtes HTTP provenant de cette origine.

```
```

5. Webhook Stripe

Le webhook Stripe doit être déclaré avant express.json().

``` 
app.post(
    "/api/payments/webhook",
    express.raw({
        type: "application/json",
    }),
    require("./controllers/paymentController").stripeWebhook
);
```
Important :

Stripe utilise le corps brut de la requête pour vérifier correctement la signature du webhook.

```
```

6. Middleware JSON

``` 
app.use(express.json());

app.use(
    express.urlencoded({
        extended: true,
    })
);
```

express.json() permet au serveur de recevoir des données au format JSON.

express.urlencoded() permet de traiter les données envoyées sous forme de formulaires.

7. Routes API

Les routes principales du backend sont organisées par fonctionnalité.

  • /api/appointments Gestion des rendez-vous.
  • /api/batteries Gestion des batteries.
  • /api/contacts Gestion des messages de contact.
  • /api/dashboard Gestion des données du dashboard.
  • /api/inverters Gestion des onduleurs.
  • /api/panels Gestion des panneaux solaires.
  • /api/payments Gestion des paiements.
  • /api/quotes Gestion des demandes de devis.
  • /api/reviews Gestion des avis clients.
  • /api/users Gestion de l'authentification et des utilisateurs.

8. Modèle Appointment

Le modèle Appointment représente un rendez-vous demandé par un client.

``` 
const appointmentSchema = new mongoose.Schema(
    {
        customerName: {
            type: String,
            required: true,
        },

        email: {
            type: String,
            required: true,
        },

        phone: {
            type: String,
            required: true,
        },

        appointmentDate: {
            type: Date,
            required: true,
        },

        address: {
            type: String,
            required: true,
        },

        message: {
            type: String,
        },

        status: {
            type: String,
            enum: [
                "Pending",
                "Confirmed",
                "Completed",
                "Cancelled"
            ],
            default: "Pending",
        },
    },
    {
        timestamps: true,
    }
);

module.exports = mongoose.model(
    "Appointment",
    appointmentSchema
);
```

Le statut permet de suivre l'évolution du rendez-vous : en attente, confirmé, terminé ou annulé.

16. Modèle User

Le modèle User gère les comptes utilisateurs de la plateforme.

``` 
const userSchema = new mongoose.Schema(
    {
        name: {
            type: String,
            required: true,
            trim: true,
        },

        email: {
            type: String,
            required: true,
            unique: true,
            lowercase: true,
            trim: true,
        },

        password: {
            type: String,
            required: true,
        },

        phone: {
            type: String,
        },

        role: {
            type: String,
            enum: [
                "admin",
                "customer"
            ],
            default: "customer",
        },

        isVerified: {
            type: Boolean,
            default: false,
        },
    },
    {
        timestamps: true,
    }
);

module.exports = mongoose.model(
    "User",
    userSchema
);
```

Le champ role distingue les deux types d'utilisateurs :

  • admin : accès aux fonctionnalités administratives.
  • customer : accès aux fonctionnalités client.

Le champ isVerified permet également de savoir si le compte utilisateur a été vérifié.

17. Gestion des routes inexistantes

``` 
app.use((req, res) => {
    res.status(404).json({
        success: false,
        message: `Route introuvable : ${req.method} ${req.originalUrl}`,
    });
});
```

Lorsqu'une URL API n'existe pas, le serveur retourne une réponse HTTP 404.

18. Gestion globale des erreurs

``` 
app.use((err, req, res, next) => {

    console.error("❌ Erreur serveur :", err);

    res.status(err.status || 500).json({
        success: false,
        message: err.message || "Erreur interne du serveur",
    });

});
```

Ce middleware permet de capturer les erreurs générées pendant le traitement des requêtes.

En cas d'erreur interne, le serveur retourne généralement le code HTTP 500.
