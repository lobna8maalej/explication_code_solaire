☀️ Frontend Documentation — Solar Energy

Explanation of React components, Axios, React Router, authentication, appointments, contacts, reviews and Admin Dashboard.

📚 1. General Overview

This part of the project corresponds to the React Frontend of the Solar Energy platform.

The components presented here allow users to create an account, log in, send a message, request an appointment and view reviews.

The system also includes an Admin Dashboard that allows administrators to view statistics and manage quote requests.

Technologies used:
  • React.js
  • React Hooks (useState, useEffect)
  • Axios for HTTP requests
  • React Router
  • LocalStorage for JWT
  • Node.js / Express REST API
  • MongoDB on the Backend

⭐ 2. Testimonials.jsx Component

The Testimonials.jsx component displays customer reviews stored in the database.

2.1 Importing Dependencies 

import { useEffect, useState } from "react";
import axios from "axios";
import "./Testimonials.css";

useState is used to create and modify the component's local state.

useEffect is used to automatically execute code after the component is loaded.

axios is used to communicate with the Backend API.

2.2 Storing Reviews 

const [reviews, setReviews] = useState([]);

Initially, the list of reviews is empty. The setReviews function is then used to update this list.

2.3 Retrieving Reviews 

useEffect(() => {

    axios
        .get("http://localhost:3000/api/reviews")

        .then((res) => {

            console.log(
                "API REVIEWS :",
                res.data
            );

        })

        .catch((error) => {

            console.log(
                "Erreur API :",
                error
            );

        });

}, []);

When the page is loaded, a GET request is sent to: 

GET /api/reviews

The Backend returns the available reviews.

2.4 Filtering Approved Reviews 

res.data.data.filter(
    review => review.status === "Approved"
)

The component only displays reviews whose status is Approved.

Why?

Reviews can be created by customers, but they must be approved by the administrator before being displayed publicly.

2.5 Displaying Stars 

{"⭐".repeat(review.rating)}

If the rating is 5, React generates:

⭐⭐⭐⭐⭐

2.6 Displaying the Review 

{reviews.map(review => (

    <div
        className="review-card"
        key={review._id}
    >

        <h3>
            {review.customerName}
        </h3>

        <p>
            {"⭐".repeat(review.rating)}
        </p>

        <p>
            {review.comment}
        </p>

        <strong>
            {review.productName}
        </strong>

    </div>

))}

map() iterates through all reviews and creates an HTML card for each review.

📅 4. Appointment.jsx Component

The Appointment component allows the customer to request an appointment with Solar Energy.

const [form, setForm] = useState({

    address: "",
    message: "",

4.3 Form Modification 

const handleChange = (e) => {

    const { name, value } = e.target;

    setForm((prev) => ({

        [name]: value,
    }));

This function retrieves the field name and its value.

For example, if the user enters Ahmed in the customerName field, React updates: 

form.customerName = "Ahmed"

);

POST /api/appointments

    message: "",

🔐 5. Auth.jsx Component

The Auth component handles both user registration and login.

5.1 Login / Registration Mode 

const [mode, setMode] = useState("login");

The initial mode is login.

When the mode is register, the form also displays the Name field.

5.2 Form Data 

const [form, setForm] = useState({

    name: "",
    email: "",
    password: "",

});

5.3 Login 

const response = await axios.post(
    "http://localhost:3000/api/users/login",
    {
        email: form.email,
        password: form.password,
    }
);

A POST request is sent to the Backend to verify the email address and password.

5.4 Retrieving the JWT 

if (response.data.token) {

    localStorage.setItem(
        "token",
        response.data.token
    );

}

If the login is successful, the Backend returns a JWT.

The token is then stored in localStorage.

Authentication flow:
User → Login → Backend → Verification → JWT → localStorage

5.5 Redirect After Login 

navigate("/products");

After a successful login, the user is redirected to the products page.

5.6 Registration 

await axios.post(
    "http://localhost:3000/api/users/register",
    {
        name: form.name,
        email: form.email,
        password: form.password,
    }
);

The registration form sends the name, email and password to the Backend.

5.7 Returning to Login 

setMode("login");

After the account is created, the form automatically returns to login mode.

5.8 Switching Login / Register 

setMode(
    mode === "login"
        ? "register"
        : "login"
);

This logic allows the user to switch between login and registration.

if (

// Format 3

This logic makes the component more flexible when the Backend response structure changes.

7.9 Updating Quote Status 

const updateQuoteStatus =
    async (id, status) => {

    const response =
        await axios.put(
            `http://localhost:3000/api/quotes/${id}`,
            {
                status: status,
            },
            {
                headers: {
                    Authorization:
                        `Bearer ${token}`,
                },
            }
        );

};

The administrator can update the status of a quote.

7.10 Available Statuses

  • Pending — Waiting
  • Reviewed — Request reviewed
  • Approved — Approved
  • Rejected — Rejected

7.11 Action Logic

Pending

👁️ Review → Reviewed

✅ Accept → Approved

❌ Reject → Rejected

Reviewed

✅ Accept → Approved

❌ Reject → Rejected

Approved:

The Dashboard indicates that the quote has been approved and that the customer can now make the payment.

Rejected:

The Dashboard indicates that the quote has been rejected.

8.10 Handling a 401 Error 

if (
    error.response?.status === 401
) {

    alert(
        "Session expirée. Veuillez vous reconnecter."
    );

    localStorage.removeItem(
        "token"
    );

    window.location.href =
        "/auth";
}

The code checks whether the Backend returns HTTP status 401.

This generally means that the token is missing, invalid or expired.

In this case:

  1. A message is displayed.
  2. The token is removed.
  3. The user is redirected to /auth.

🔄 9. Overall Frontend Operation

The different components communicate with the Backend through REST APIs.

👤 User

↓

React

↓

Axios

↓

Express API

↓

MongoDB

Main APIs Used

  • POST /api/users/register — registration
  • POST /api/users/login — login
  • GET /api/reviews — retrieve reviews
  • POST /api/appointments — create an appointment
  • POST /api/contacts — create a message
  • GET /api/dashboard — administrator statistics
  • GET /api/quotes — retrieve quotes
  • PUT /api/quotes/:id — update quote status
  • GET /api/contacts — retrieve messages

🔑 10. JWT Authentication

The system uses a JWT token to protect certain administrator routes.

1. The user logs in.

↓

2. The Backend verifies the credentials.

↓

3. The Backend generates a JWT.

↓

4. React stores the JWT in localStorage.

↓

5. Axios sends the JWT with protected requests.

↓

6. The Backend Middleware verifies the token. 

Authorization: Bearer TOKEN
