🔐 2. Middleware verifyToken

Le middleware verifyToken permet de protéger certaines routes de l'API grâce à un token JWT.

Import de jsonwebtoken

const jwt = require("jsonwebtoken");

La bibliothèque jsonwebtoken permet de créer et vérifier des tokens JWT.

Création du middleware

const verifyToken = (req, res, next) => {

Le middleware reçoit trois paramètres :

  • req : la requête HTTP
  • res : la réponse HTTP
  • next : permet de continuer vers la prochaine fonction

Récupération du header Authorization

console.log(
    "Authorization :",
    req.headers.authorization
);

const token =
    req.headers.authorization?.split(" ")[1];

Le frontend envoie généralement le token sous cette forme : 

Authorization: Bearer TOKEN

La méthode split(" ") sépare : 

Bearer
TOKEN

Le deuxième élément, avec l'index [1], correspond au token.

Vérification de l'existence du token

if (!token) {

    return res.status(401).json({

        success: false,

        message: "Accès refusé, token manquant",

    });

}

Si aucun token n'est envoyé, le serveur retourne une erreur 401 Unauthorized.

⚠️ Important : Sans token valide, l'utilisateur ne peut pas accéder aux routes protégées.

Vérification de JWT_SECRET

console.log(
    "JWT_SECRET disponible :",
    !!process.env.JWT_SECRET
);

Le serveur vérifie si la variable d'environnement JWT_SECRET existe.

Cette clé secrète est utilisée pour vérifier l'authenticité du JWT.

Vérification du token

const decoded = jwt.verify(
    token,
    process.env.JWT_SECRET
);

Si le token est valide, JWT retourne les informations contenues dans le token.

Stockage de l'utilisateur

req.user = decoded;

next();

Les informations décodées sont stockées dans req.user.

Les contrôleurs suivants peuvent donc accéder aux informations de l'utilisateur connecté.

Gestion des erreurs

catch (error) {

    console.log(
        "ERREUR JWT :",
        error.message
    );

    return res.status(401).json({

        success: false,

        message: "Token invalide",

    });

}

Si le token est expiré, incorrect ou falsifié, le serveur retourne une erreur 401.

✅ Résultat : Le middleware protège les routes nécessitant une authentification.

📁 3. Configuration de Multer

Multer est utilisé pour gérer l'envoi de fichiers depuis le frontend vers le backend.

Import

const multer = require("multer");

Stockage en mémoire

const storage = multer.memoryStorage();

Les fichiers reçus sont conservés temporairement en mémoire RAM au lieu d'être directement enregistrés dans un dossier.

Configuration de l'upload

const upload = multer({

    storage,

    limits: {

        fileSize: 5 * 1024 * 1024,

    },

});

La taille maximale d'un fichier est de : 

5 * 1024 * 1024 = 5 MB
💡 Pourquoi limiter la taille ? Cela permet d'éviter que des fichiers trop volumineux consomment trop de mémoire ou ralentissent le serveur.

Export

module.exports = upload;

Le middleware peut ensuite être utilisé dans les routes.

⭐ 4. Review Controller

Le contrôleur des avis permet de gérer les avis clients.

Import du modèle

const Review = require("../models/Review");

Le modèle Review permet d'interagir avec la collection MongoDB des avis.

Import de l'envoi d'e-mail

const sendEmail =
    require("../utils/sendEmail");

Cette fonction permet d'envoyer un e-mail au client après la création de son avis.

4.1 Créer un avis

exports.createReview = async (req, res) => {

    try {

        const review =
            await Review.create(req.body);

        ...

    }

    catch (error) {

        ...

    }

};

req.body contient les informations envoyées par le frontend.

Par exemple :

{
    "customerName": "Ahmed Ben Ali",
    "email": "ahmed@gmail.com",
    "rating": 5,
    "comment": "Excellent produit",
    "productType": "Panel",
    "productName": "Jinko Solar"
}

Enregistrement dans MongoDB

const review =
    await Review.create(req.body);

Mongoose crée un nouveau document dans la collection reviews.

Envoi d'un e-mail

if (review.email) {

    await sendEmail({

        to: review.email,

        subject: "Merci pour votre avis",

        html: `...`

    });

}

Si le client possède une adresse e-mail, le serveur lui envoie un message de confirmation.

Réponse HTTP

res.status(201).json({

    success: true,

    data: review,

});

Le code HTTP 201 signifie que la ressource a été créée.

4.2 Récupérer tous les avis

exports.getReviews = async (req, res) => {

    const reviews =
        await Review.find()
        .sort({ createdAt: -1 });

};

Review.find() récupère tous les avis.

sort({ createdAt: -1 }) affiche les avis les plus récents en premier.

Réponse

res.status(200).json({

    success: true,

    count: reviews.length,

    data: reviews,

});

La réponse contient :

  • success : indique si la requête a réussi
  • count : nombre total d'avis
  • data : liste des avis

4.3 Récupérer un avis par ID

const review =
    await Review.findById(req.params.id);

req.params.id contient l'identifiant de l'avis présent dans l'URL.

Exemple :

GET /api/reviews/6a70e9b8e7dd0d3a96e97287

4.4 Modifier un avis

const review =
    await Review.findByIdAndUpdate(

        req.params.id,

        req.body,

        {
            new: true,
            runValidators: true
        }

    );

Cette méthode recherche l'avis par son ID et met à jour les données envoyées dans req.body.

new: true permet de retourner la version mise à jour.

runValidators: true permet d'appliquer les validations du modèle Mongoose.

4.5 Supprimer un avis

const review =
    await Review.findByIdAndDelete(
        req.params.id
    );

L'avis correspondant à l'identifiant est supprimé de MongoDB.

✅ Les opérations disponibles sont :

CREATE → créer un avis
READ → récupérer les avis
UPDATE → modifier un avis
DELETE → supprimer un avis

📄 5. Quote Controller

Le contrôleur Quote permet de gérer les demandes de devis solaires des clients.

Import du modèle

const Quote =
    require("../models/Quote");

Import de l'e-mail

const sendEmail =
    require("../utils/sendEmail");

5.1 Créer une demande de devis

exports.createQuote =
async (req, res) => {

    try {

        const quote =
            await Quote.create(req.body);

        ...

    }

    catch(error) {

        ...

    }

};

Les informations envoyées par le formulaire sont récupérées avec req.body.

Exemple :

{
    "customerName": "Ahmed Ben Ali",
    "email": "ahmed@gmail.com",
    "phone": "58229886",
    "address": "Sfax",
    "serviceType": "Residential",
    "estimatedConsumption": 500,
    "budget": 10000,
    "message": "Installation solaire"
}

Création du devis

const quote =
    await Quote.create(req.body);

Mongoose enregistre la demande dans MongoDB.

Envoi d'un e-mail de confirmation

if (quote.email) {

    await sendEmail({

        to: quote.email,

        subject:
        "Confirmation de votre demande de devis solaire",

        html: `...`

    });

}

Le client reçoit automatiquement un e-mail confirmant la réception de sa demande.

Informations envoyées dans l'e-mail

  • Nom du client
  • Adresse e-mail
  • Téléphone
  • Adresse
  • Type d'installation
  • Consommation estimée
  • Budget
  • Message

Réponse du serveur

res.status(201).json({

    success: true,

    data: quote

});

Le serveur retourne la demande de devis créée.

5.2 Récupérer tous les devis

const quotes =
    await Quote.find()
    .sort({ createdAt: -1 });

Tous les devis sont récupérés et triés du plus récent au plus ancien.

5.3 Récupérer un devis par ID

const quote =
    await Quote.findById(
        req.params.id
    );

Cette fonction permet de récupérer un devis précis.

5.4 Modifier un devis

const quote =
    await Quote.findByIdAndUpdate(

        req.params.id,

        req.body,

        {
            new: true,
            runValidators: true
        }

    );

Cette fonctionnalité peut notamment être utilisée par l'administration pour modifier le statut d'un devis.

Par exemple :

{
    "status": "Approved"
}

Le statut du devis peut être :

  • Pending
  • Reviewed
  • Approved
  • Rejected

5.5 Supprimer un devis

const quote =
    await Quote.findByIdAndDelete(
        req.params.id
    );

Cette fonction supprime définitivement le devis correspondant à son ID.

⚠️ 8. Gestion des erreurs

Les contrôleurs utilisent try...catch afin d'éviter que les erreurs provoquent l'arrêt du serveur.

Erreur de validation

res.status(400).json({

    success: false,

    message: error.message

});

Le code 400 indique généralement que les données envoyées sont incorrectes ou ne respectent pas le modèle.

Ressource introuvable

res.status(404).json({

    success: false,

    message: "Avis introuvable"

});

Le code 404 est utilisé lorsqu'un avis ou un devis n'existe pas.

Erreur serveur

res.status(500).json({

    success: false,

    message: error.message

});

Le code 500 indique une erreur interne du serveur.
