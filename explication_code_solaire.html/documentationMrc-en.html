📚 1. General Overview

This part of the backend is a REST API developed with Node.js, Express and MongoDB/Mongoose.

It allows the management of several features of the Solar Energy platform:

  • 🔐 Authentication with JWT
  • 📅 Appointment management
  • ☀️ Solar panel management
  • 🔋 Battery management
  • ⚡ Inverter management
  • 📄 Quote request management
  • 💳 Payment management
  • ⭐ Customer review management
  • 📩 Contact management
  • 📊 Dashboard management
  • 📁 File management with Multer

🔐 2. verifyToken Middleware

The verifyToken middleware protects certain API routes using a JWT token.

Importing jsonwebtoken

 
const jwt = require("jsonwebtoken");

The jsonwebtoken library allows you to create and verify JWT tokens.

Creating the middleware

 
const verifyToken = (req, res, next) => {

The middleware receives three parameters:

  • req: the HTTP request
  • res: the HTTP response
  • next: allows the request to continue to the next function

Retrieving the Authorization header

 
console.log( 
    "Authorization :", 
    req.headers.authorization 
); 
 
const token = 
    req.headers.authorization?.split(" ")[1];

The frontend generally sends the token in the following format: 

 
Authorization: Bearer TOKEN

The split(" ") method separates: 

 
Bearer 
TOKEN

The second element, with index [1], corresponds to the token.

Checking whether the token exists

 
if (!token) { 
 
    return res.status(401).json({ 
 
        success: false, 
 
        message: "Accès refusé, token manquant", 
 
    }); 
 
}

If no token is sent, the server returns a 401 Unauthorized error.

⚠️ Important: Without a valid token, the user cannot access protected routes.

Checking JWT_SECRET

 
console.log( 
    "JWT_SECRET disponible :", 
    !!process.env.JWT_SECRET 
);

The server checks whether the environment variable JWT_SECRET exists.

This secret key is used to verify the authenticity of the JWT.

Verifying the token

 
const decoded = jwt.verify( 
    token, 
    process.env.JWT_SECRET 
);

If the token is valid, JWT returns the information contained in the token.

Storing the user

 
req.user = decoded; 
 
next();

The decoded information is stored in req.user.

The following controllers can therefore access the information of the logged-in user.

Error handling

 
catch (error) { 
 
    console.log( 
        "ERREUR JWT :", 
        error.message 
    ); 
 
    return res.status(401).json({ 
 
        success: false, 
 
        message: "Token invalide", 
 
    }); 
 
}

If the token is expired, incorrect, or forged, the server returns a 401 error.

✅ Result: The middleware protects routes that require authentication.

📁 3. Multer Configuration

Multer is used to handle file uploads from the frontend to the backend.

Import

 
const multer = require("multer");

Memory Storage

 
const storage = multer.memoryStorage();

Received files are temporarily stored in RAM instead of being directly saved in a folder.

Upload Configuration

 
const upload = multer({ 
 
    storage, 
 
    limits: { 
 
        fileSize: 5 * 1024 * 1024, 
 
    }, 
 
});

The maximum file size is: 

 
5 * 1024 * 1024 = 5 MB
💡 Why limit the file size? This helps prevent oversized files from consuming too much memory or slowing down the server.

Export

 
module.exports = upload;

The middleware can then be used in the routes.

⭐ 4. Review Controller

The review controller allows customer reviews to be managed.

Model Import

 
const Review = require("../models/Review");

The Review model allows interaction with the MongoDB collection containing the reviews.

Email Sending Import

 
const sendEmail = 
    require("../utils/sendEmail");

This function allows an email to be sent to the customer after their review has been created.

4.1 Create a Review

 
exports.createReview = async (req, res) => { 
 
    try { 
 
        const review = 
            await Review.create(req.body); 
 
        ... 
 
    } 
 
    catch (error) { 
 
        ... 
 
    } 
 
};

req.body contains the information sent by the frontend.

For example:

 
{ 
    "customerName": "Ahmed Ben Ali", 
    "email": "ahmed@gmail.com", 
    "rating": 5, 
    "comment": "Excellent produit", 
    "productType": "Panel", 
    "productName": "Jinko Solar" 
}

Saving to MongoDB

 
const review = 
    await Review.create(req.body);

Mongoose creates a new document in the reviews collection.

Sending an Email

 
if (review.email) { 
 
    await sendEmail({ 
 
        to: review.email, 
 
        subject: "Merci pour votre avis", 
 
        html: `...` 
 
    }); 
 
}

If the customer has an email address, the server sends them a confirmation message.

HTTP Response

 
res.status(201).json({ 
 
    success: true, 
 
    data: review, 
 
});
The customer automatically receives an email confirming the receipt of their request.

Information Sent in the Email

  • Customer name
  • Email address
  • Phone number
  • Address
  • Installation type
  • Estimated consumption
  • Budget
  • Message

Server Response

 
res.status(201).json({ 
 
    success: true, 
 
    data: quote 
 
});

The server returns the created quote request.

5.2 Retrieve All Quotes

 
const quotes = 
    await Quote.find() 
    .sort({ createdAt: -1 });

All quotes are retrieved and sorted from newest to oldest.

5.3 Retrieve a Quote by ID

 
const quote = 
    await Quote.findById( 
        req.params.id 
    );

This function allows a specific quote to be retrieved.

5.4 Update a Quote

 
const quote = 
    await Quote.findByIdAndUpdate( 
 
        req.params.id, 
 
        req.body, 
 
        { 
            new: true, 
            runValidators: true 
        } 
 
    );

This feature can be used by the administration team, for example, to update the status of a quote.

For example:

 
{ 
    "status": "Approved" 
}

The quote status can be:

  • Pending
  • Reviewed
  • Approved
  • Rejected

5.5 Delete a Quote

 
const quote = 
    await Quote.findByIdAndDelete( 
        req.params.id 
    );

This function permanently deletes the quote corresponding to its ID.
