# 29 — Configuration principale du Backend avec Express

Le fichier app.js constitue le point central de configuration du Backend Solar Energy.

Il permet d'initialiser Express, de configurer CORS, de gérer les requêtes JSON, d'enregistrer les différentes routes de l'API, de gérer le webhook Stripe et de traiter les erreurs et les routes inexistantes.

Importation d'Express et de CORS 

const express = require("express");
const cors = require("cors");

const app = express();

express permet de créer et de configurer le serveur Backend.

cors permet d'autoriser les requêtes provenant du frontend React.

express() crée l'application Express qui sera ensuite utilisée pour enregistrer les middlewares et les routes.

Configuration de CORS 

app.use(
    cors({
        origin: "http://localhost:5173",
        methods: [
            "GET",
            "POST",
            "PUT",
            "DELETE",
            "PATCH"
        ],
        credentials: true,
    })
);

CORS permet au Backend d'accepter les requêtes envoyées par le frontend React.

Dans ce projet, le frontend fonctionne sur :

Frontend :
http://localhost:5173

La propriété origin autorise donc précisément cette origine.

La propriété methods indique les méthodes HTTP autorisées par le serveur.

credentials: true permet l'utilisation d'informations d'identification dans les requêtes lorsque cela est nécessaire.

Gestion du Webhook Stripe 

app.post(
    "/api/payments/webhook",

    express.raw({
        type: "application/json",
    }),

    require("./controllers/paymentController").stripeWebhook
);

Cette route reçoit les notifications envoyées par Stripe concernant les événements de paiement.

Le webhook utilise express.raw() afin de recevoir le corps original de la requête sous forme de données brutes.

Important :

Le webhook Stripe est placé avant express.json(). Cette organisation est nécessaire car Stripe peut avoir besoin du corps brut de la requête pour vérifier correctement la signature du webhook.

Middleware JSON 

app.use(express.json());

Ce middleware permet à Express de lire les requêtes contenant des données JSON.

Par exemple, lorsqu'un formulaire React envoie : 

{
    "name": "Lobna",
    "email": "client@example.com",
    "phone": "58229886"
}

Express transforme automatiquement les données JSON afin qu'elles soient accessibles dans : req.body.

Gestion des données URL-encoded 

app.use(
    express.urlencoded({
        extended: true,
    })
);

Ce middleware permet au serveur de traiter les données envoyées sous le format application/x-www-form-urlencoded.

L'option extended: true permet également de gérer des structures de données plus complexes.

Gestion des routes inexistantes — 404 

app.use((req, res) => {

    res.status(404).json({
        success: false,
        message:
            `Route introuvable :
            ${req.method}
            ${req.originalUrl}`,
    });

});

Ce middleware est exécuté lorsqu'aucune route précédente ne correspond à la requête reçue.

Le serveur retourne alors le statut HTTP 404.

Exemple :

Si le client demande :
GET /api/test123

et que cette route n'existe pas, le serveur retourne une erreur indiquant que la route est introuvable.

Gestion globale des erreurs 

app.use((err, req, res, next) => {

    console.error(
        "❌ Erreur serveur :",
        err
    );

    res.status(err.status || 500).json({

        success: false,

        message:
            err.message ||
            "Erreur interne du serveur",

    });

});

Ce middleware permet de centraliser la gestion des erreurs du Backend.

Lorsqu'une erreur est transmise à Express, elle peut être traitée par ce middleware.

Le serveur retourne un code HTTP correspondant à l'erreur ou, par défaut, le code 500.

Structure de la réponse :

success: false
message: "Erreur..."

Exportation de l'application 

module.exports = app;

Cette instruction permet d'exporter l'application Express afin qu'elle puisse être utilisée par le fichier principal du serveur, généralement server.js ou index.js.

Flux global du Backend

Architecture :

React → Axios → Express → CORS → Route API → Middleware → Controller → Model Mongoose → MongoDB

Puis la réponse revient vers le frontend :

MongoDB → Controller → JSON → Express → Axios → React

Ordre de traitement des requêtes

  1. Le frontend React envoie une requête HTTP.
  2. CORS vérifie si l'origine du frontend est autorisée.
  3. Le webhook Stripe est traité séparément avec express.raw() lorsqu'il s'agit de /api/payments/webhook.
  4. express.json() analyse les données JSON.
  5. Express recherche la route correspondante.
  6. Le middleware éventuel, comme verifyToken, est exécuté.
  7. Le controller traite la demande.
  8. Le model Mongoose communique avec MongoDB.
  9. Le controller retourne une réponse JSON.
  10. Axios reçoit la réponse dans le frontend React.

Élément Rôle

Stripe Webhook Réception des événements de paiement
404 Gestion des routes inexistantes

module.exports Exportation de l'application Express

Le fichier app.js centralise la configuration du Backend Solar Energy. Il connecte les différentes routes, les middlewares, l'authentification, Stripe et les controllers afin de construire une API REST organisée et maintenable.

# 31 — Configuration du fichier .env

Le fichier .env contient les variables d'environnement utilisées par le Backend Solar Energy.

Il permet de centraliser la configuration du serveur et les informations sensibles nécessaires aux différents services utilisés par l'application : MongoDB, JWT, Stripe, Cloudinary et l'envoi d'e-mails.

⚠️ Attention :

Le fichier .env peut contenir des informations sensibles. Il ne doit jamais être publié dans GitHub ou intégré directement dans le frontend React.

Exemple de configuration du fichier .env 

PORT=3000
```

MONGO_URI=mongodb://127.0.0.1:27017/solar_db

JWT_SECRET=YOUR_JWT_SECRET

STRIPE_SECRET_KEY=YOUR_STRIPE_SECRET_KEY

CLOUDINARY_CLOUD_NAME=YOUR_CLOUDINARY_CLOUD_NAME

CLOUDINARY_API_KEY=YOUR_CLOUDINARY_API_KEY

CLOUDINARY_API_SECRET=YOUR_CLOUDINARY_API_SECRET

EMAIL_USER=YOUR_EMAIL

EMAIL_PASS=YOUR_EMAIL_APP_PASSWORD
```

Ces valeurs sont chargées automatiquement par dotenv lorsque le Backend démarre.

Chargement du fichier .env avec dotenv 

require("dotenv").config();

Cette instruction charge les variables définies dans le fichier .env et les rend accessibles dans Node.js grâce à process.env.

Fonctionnement :

.env → dotenv.config() → process.env

Par exemple, si le fichier .env contient : 

PORT=3000

le code JavaScript peut récupérer cette valeur avec : 

process.env.PORT

Variable PORT 

PORT=3000

La variable PORT définit le port sur lequel le serveur Express écoute les requêtes HTTP.

Dans le fichier server.js, cette variable est récupérée avec : 

const PORT = process.env.PORT || 3000;

Si PORT est défini dans le fichier .env, sa valeur est utilisée. Sinon, le serveur utilise le port 3000 comme valeur par défaut.

Configuration actuelle :

PORT=3000

Le Backend est donc accessible sur :

http://localhost:3000

Variable MONGO_URI 

MONGO_URI=mongodb://127.0.0.1:27017/solar_db

La variable MONGO_URI contient l'adresse utilisée par Mongoose pour se connecter à MongoDB.

Dans ce projet, la base de données MongoDB utilisée s'appelle solar_db.

Dans server.js, la connexion est réalisée avec : 

mongoose
.connect(process.env.MONGO_URI)
Flux de connexion :

.env → MONGO_URI → mongoose.connect() → MongoDB → solar_db

Variable JWT_SECRET 

JWT_SECRET=YOUR_JWT_SECRET

La variable JWT_SECRET contient une clé secrète utilisée par le Backend pour sécuriser les tokens JWT.

Elle intervient notamment dans le processus d'authentification des utilisateurs.

Le Backend peut récupérer cette valeur avec : 

process.env.JWT_SECRET
🔐 Sécurité :

La valeur réelle de JWT_SECRET doit rester confidentielle. Elle ne doit pas être publiée dans GitHub ou dans une documentation publique.

Variable STRIPE_SECRET_KEY 

STRIPE_SECRET_KEY=YOUR_STRIPE_SECRET_KEY

Cette variable contient la clé secrète permettant au Backend de communiquer avec Stripe.

Elle est utilisée côté serveur pour effectuer les opérations liées aux paiements, notamment la création de sessions Stripe Checkout.

Le Backend peut récupérer la clé avec : 

process.env.STRIPE_SECRET_KEY
⚠️ Important :

Une clé secrète Stripe ne doit jamais être placée dans le frontend React.

Elle doit uniquement être utilisée côté Backend et stockée dans une variable d'environnement sécurisée.
