# 29 — Configuración principal del Backend con Express

El archivo app.js constituye el punto central de configuración del Backend Solar Energy.

Permite inicializar Express, configurar CORS, gestionar las solicitudes JSON, registrar las diferentes rutas de la API, gestionar el webhook de Stripe y tratar los errores y las rutas inexistentes.

Importación de Express y CORS 

const express = require("express");
const cors = require("cors");

const app = express();

express permite crear y configurar el servidor Backend.

cors permite autorizar las solicitudes provenientes del frontend React.

express() crea la aplicación Express que posteriormente se utilizará para registrar los middlewares y las rutas.

Configuración de CORS 

app.use(
    cors({
        origin: "http://localhost:5173",
        methods: [
            "GET",
            "POST",
            "PUT",
            "DELETE",
            "PATCH"
        ],
        credentials: true,
    })
);

CORS permite al Backend aceptar las solicitudes enviadas por el frontend React.

En este proyecto, el frontend funciona en:

Frontend:
http://localhost:5173

La propiedad origin autoriza específicamente este origen.

La propiedad methods indica los métodos HTTP autorizados por el servidor.

credentials: true permite utilizar información de autenticación en las solicitudes cuando sea necesario.

Gestión del Webhook de Stripe 

app.post(
    "/api/payments/webhook",

    express.raw({
        type: "application/json",
    }),

    require("./controllers/paymentController").stripeWebhook
);

Esta ruta recibe las notificaciones enviadas por Stripe relacionadas con los eventos de pago.

El webhook utiliza express.raw() para recibir el cuerpo original de la solicitud en forma de datos sin procesar.

Importante:

El webhook de Stripe se coloca antes de express.json(). Esta organización es necesaria porque Stripe puede necesitar el cuerpo original de la solicitud para verificar correctamente la firma del webhook.

Middleware JSON 

app.use(express.json());

Este middleware permite a Express leer las solicitudes que contienen datos JSON.

Por ejemplo, cuando un formulario React envía: 

{
    "name": "Lobna",
    "email": "client@example.com",
    "phone": "58229886"
}

Express transforma automáticamente los datos JSON para que sean accesibles mediante: req.body.

Gestión de datos URL-encoded 

app.use(
    express.urlencoded({
        extended: true,
    })
);

Este middleware permite al servidor procesar los datos enviados mediante el formato application/x-www-form-urlencoded.

La opción extended: true también permite gestionar estructuras de datos más complejas.

Gestión de rutas inexistentes — 404 

app.use((req, res) => {

    res.status(404).json({
        success: false,
        message:
            `Route introuvable :
            ${req.method}
            ${req.originalUrl}`,
    });

});

Este middleware se ejecuta cuando ninguna ruta anterior coincide con la solicitud recibida.

El servidor devuelve entonces el estado HTTP 404.

Ejemplo:

Si el cliente solicita:
GET /api/test123

y esta ruta no existe, el servidor devuelve un error indicando que la ruta no se encuentra.

Gestión global de errores 

app.use((err, req, res, next) => {

    console.error(
        "❌ Erreur serveur :",
        err
    );

    res.status(err.status || 500).json({

        success: false,

        message:
            err.message ||
            "Erreur interne du serveur",

    });

});

Este middleware permite centralizar la gestión de los errores del Backend.

Cuando se transmite un error a Express, puede ser gestionado por este middleware.

El servidor devuelve un código HTTP correspondiente al error o, por defecto, el código 500.

Estructura de la respuesta:

success: false
message: "Erreur..."

Exportación de la aplicación 

module.exports = app;

Esta instrucción permite exportar la aplicación Express para que pueda ser utilizada por el archivo principal del servidor, generalmente server.js o index.js.

Flujo global del Backend

Arquitectura:

React → Axios → Express → CORS → Ruta API → Middleware → Controller → Model Mongoose → MongoDB

Luego, la respuesta vuelve al frontend:

MongoDB → Controller → JSON → Express → Axios → React

Orden de procesamiento de las solicitudes

  1. El frontend React envía una solicitud HTTP.
  2. CORS verifica si el origen del frontend está autorizado.
  3. El webhook de Stripe se procesa por separado mediante express.raw() cuando se trata de /api/payments/webhook.
  4. express.json() analiza los datos JSON.
  5. Express busca la ruta correspondiente.
  6. El middleware correspondiente, como verifyToken, se ejecuta.
  7. El controller procesa la solicitud.
  8. El model Mongoose se comunica con MongoDB.
  9. El controller devuelve una respuesta JSON.
  10. Axios recibe la respuesta en el frontend React.

# 31 — Configuración del archivo .env

El archivo .env contiene las variables de entorno utilizadas por el Backend Solar Energy.

Permite centralizar la configuración del servidor y la información sensible necesaria para los diferentes servicios utilizados por la aplicación: MongoDB, JWT, Stripe, Cloudinary y el envío de correos electrónicos.

⚠️ Atención:

El archivo .env puede contener información sensible. Nunca debe publicarse en GitHub ni integrarse directamente en el frontend React.

Ejemplo de configuración del archivo .env 

PORT=3000

MONGO_URI=mongodb://127.0.0.1:27017/solar_db

JWT_SECRET=YOUR_JWT_SECRET

STRIPE_SECRET_KEY=YOUR_STRIPE_SECRET_KEY

CLOUDINARY_CLOUD_NAME=YOUR_CLOUDINARY_CLOUD_NAME

CLOUDINARY_API_KEY=YOUR_CLOUDINARY_API_KEY

CLOUDINARY_API_SECRET=YOUR_CLOUDINARY_API_SECRET

EMAIL_USER=YOUR_EMAIL

EMAIL_PASS=YOUR_EMAIL_APP_PASSWORD

Estos valores se cargan automáticamente mediante dotenv cuando se inicia el Backend.

Carga del archivo .env con dotenv 

require("dotenv").config();

Esta instrucción carga las variables definidas en el archivo .env y las hace accesibles en Node.js mediante process.env.

Funcionamiento:

.env → dotenv.config() → process.env

Por ejemplo, si el archivo .env contiene: 

PORT=3000

el código JavaScript puede recuperar este valor mediante: 

process.env.PORT

Variable PORT 

PORT=3000

La variable PORT define el puerto en el que el servidor Express escucha las solicitudes HTTP.

En el archivo server.js, esta variable se obtiene mediante: 

const PORT = process.env.PORT || 3000;

Si PORT está definido en el archivo .env, se utiliza su valor. De lo contrario, el servidor utiliza el puerto 3000 como valor predeterminado.

Configuración actual:

PORT=3000

Por lo tanto, el Backend está disponible en:

http://localhost:3000
