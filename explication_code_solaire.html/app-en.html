# 29 — Main Backend Configuration with Express

The app.js file is the central configuration point of the Solar Energy Backend.

It allows Express to be initialized, CORS to be configured, JSON requests to be handled, the different API routes to be registered, the Stripe webhook to be handled, and errors and non-existent routes to be processed.

Importing Express and CORS 

const express = require("express");
const cors = require("cors");

const app = express();

express is used to create and configure the Backend server.

cors allows requests coming from the React frontend.

express() creates the Express application that will then be used to register middlewares and routes.

Global Error Handling 

app.use((err, req, res, next) => {

    console.error(
        "❌ Erreur serveur :",

    res.status(err.status || 500).json({

            "Erreur interne du serveur",

This middleware allows Backend errors to be handled centrally.

When an error is passed to Express, it can be handled by this middleware.

The server returns an HTTP status code corresponding to the error or, by default, status code 500.

Response structure:

Exporting the Application 

module.exports = app;

This statement exports the Express application so that it can be used by the main server file, usually server.js or index.js.

Overall Backend Flow

Architecture:

React → Axios → Express → CORS → API Route → Middleware → Controller → Mongoose Model → MongoDB

Then the response returns to the frontend:

MongoDB → Controller → JSON → Express → Axios → React

Request Processing Order

  1. The React frontend sends an HTTP request.
  2. CORS checks whether the frontend origin is authorized.
  3. The Stripe webhook is handled separately using express.raw() when the request is made to /api/payments/webhook.
  4. express.json() parses the JSON data.
  5. Express searches for the corresponding route.
  6. Any required middleware, such as verifyToken, is executed.
  7. The controller processes the request.
  8. The Mongoose model communicates with MongoDB.
  9. The controller returns a JSON response.
  10. Axios receives the response in the React frontend.

# 31 — .env File Configuration

The .env file contains the environment variables used by the Solar Energy Backend.

It allows the server configuration and the sensitive information required by the different services used by the application to be centralized: MongoDB, JWT, Stripe, Cloudinary and email delivery.

⚠️ Warning:

The .env file may contain sensitive information. It must never be published on GitHub or directly included in the React frontend.

Example of .env File Configuration 

PORT=3000

MONGO_URI=mongodb://127.0.0.1:27017/solar_db

JWT_SECRET=YOUR_JWT_SECRET

STRIPE_SECRET_KEY=YOUR_STRIPE_SECRET_KEY

CLOUDINARY_CLOUD_NAME=YOUR_CLOUDINARY_CLOUD_NAME

CLOUDINARY_API_KEY=YOUR_CLOUDINARY_API_KEY

CLOUDINARY_API_SECRET=YOUR_CLOUDINARY_API_SECRET

EMAIL_USER=YOUR_EMAIL

EMAIL_PASS=YOUR_EMAIL_APP_PASSWORD

These values are automatically loaded by dotenv when the Backend starts.

Loading the .env File with dotenv 

require("dotenv").config();

This statement loads the variables defined in the .env file and makes them accessible in Node.js through process.env.

How it works:

.env → dotenv.config() → process.env

For example, if the .env file contains: 

PORT=3000

the JavaScript code can retrieve this value using: 

process.env.PORT

PORT Variable 

PORT=3000

The PORT variable defines the port on which the Express server listens for HTTP requests.

In the server.js file, this variable is retrieved using: 

const PORT = process.env.PORT || 3000;

If PORT is defined in the .env file, its value is used. Otherwise, the server uses port 3000 as the default value.

Current Configuration:

PORT=3000

The Backend is therefore accessible at:

http://localhost:3000

MONGO_URI Variable 

MONGO_URI=mongodb://127.0.0.1:27017/solar_db

The MONGO_URI variable contains the address used by Mongoose to connect to MongoDB.

In this project, the MongoDB database used is called solar_db.

In server.js, the connection is established using: 

mongoose
.connect(process.env.MONGO_URI)
Connection Flow:

.env → MONGO_URI → mongoose.connect() → MongoDB → solar_db

JWT_SECRET Variable 

JWT_SECRET=YOUR_JWT_SECRET

The JWT_SECRET variable contains a secret key used by the Backend to secure JWT tokens.

It is mainly involved in the user authentication process.

The Backend can retrieve this value using: 

process.env.JWT_SECRET
🔐 Security:

The actual value of JWT_SECRET must remain confidential. It must not be published on GitHub or in public documentation.

STRIPE_SECRET_KEY Variable 

STRIPE_SECRET_KEY=YOUR_STRIPE_SECRET_KEY

This variable contains the secret key that allows the Backend to communicate with Stripe.

It is used on the server side to perform payment-related operations, including the creation of Stripe Checkout sessions.

The Backend can retrieve the key using: 

process.env.STRIPE_SECRET_KEY
⚠️ Important:

A Stripe secret key must never be placed in the React frontend.

It must only be used on the Backend and stored in a secure environment variable.

Cloudinary Variables 

CLOUDINARY_CLOUD_NAME=YOUR_CLOUDINARY_CLOUD_NAME

CLOUDINARY_API_KEY=YOUR_CLOUDINARY_API_KEY

CLOUDINARY_API_SECRET=YOUR_CLOUDINARY_API_SECRET

These three variables allow the Backend to connect to the Cloudinary service to manage images and files used by the application.

Variable Role
CLOUDINARY_CLOUD_NAME Identifies the Cloudinary account being used.
CLOUDINARY_API_KEY Identifies the API key used by the application.
CLOUDINARY_API_SECRET Allows secure authentication with Cloudinary.

The variables can be retrieved in the Backend using: 

process.env.CLOUDINARY_CLOUD_NAME

process.env.CLOUDINARY_API_KEY

process.env.CLOUDINARY_API_SECRET
🔐 Security:

The CLOUDINARY_API_SECRET variable must remain secret and must never be exposed in the frontend or in a public repository.

Email Delivery Variables 

EMAIL_USER=YOUR_EMAIL

EMAIL_PASS=YOUR_EMAIL_APP_PASSWORD

These variables allow the Backend to authenticate with the email service used to send messages.

Variable Role
EMAIL_USER Email address used by the Backend to send messages.

The Backend can access this information using: 

process.env.EMAIL_USER

process.env.EMAIL_PASS
