Backend Technical Documentation

Node.js • Express • MongoDB • Mongoose

1. Backend Overview

The backend of the Solar Energy platform is developed using Node.js and Express.js.

It manages users, solar products, quote requests, appointments, contacts, payments, and customer reviews.

Data is stored in a MongoDB database and managed using Mongoose.

2. Express Server Configuration

The main backend file initializes Express, configures CORS, middlewares, and the different API routes.

Application Creation

const express = require("express");
const cors = require("cors");

const app = express();

express is used to create the HTTP server, while cors allows communication between the React frontend and the backend.

3. Route Import

Each feature has its own route file.

This organization makes it possible to separate the features and make the backend easier to maintain.

4. CORS Configuration

app.use(
    cors({
        origin: "http://localhost:5173", 
        methods: ["GET", "POST", "PUT", "DELETE", "PATCH"], 
        credentials: true, 
    }) 
);

The frontend runs here on port 5173.

The CORS middleware allows HTTP requests coming from this origin.

5. Stripe Webhook

The Stripe webhook must be declared before express.json(). 

app.post( 
    "/api/payments/webhook", 
    express.raw({ 
        type: "application/json", 
    }), 
    require("./controllers/paymentController").stripeWebhook 
);
``` Important:

Stripe uses the raw request body to correctly verify the webhook signature.

6. JSON Middleware

app.use(express.json()); 
 
app.use( 
    express.urlencoded({ 
        extended: true, 
    })

express.json() allows the server to receive data in JSON format.

express.urlencoded() allows the server to process data submitted through forms.

8. Appointment Model

The Appointment model represents an appointment requested by a customer. 

const appointmentSchema = new mongoose.Schema( 
    { 
        customerName: { 
            type: String, 
            required: true, 
        }, 
 
        email: { 
            type: String, 
            required: true, 
        }, 
 
        phone: { 
            type: String, 
            required: true, 
        }, 
 
        appointmentDate: { 
            type: Date, 
            required: true, 
        }, 
 
        address: { 
            type: String, 
            required: true, 
        }, 
 
        message: { 
            type: String, 
        }, 
 
        status: { 
            type: String, 
            enum: [ 
                "Pending", 
                "Confirmed", 
                "Completed", 
                "Cancelled" 
            ], 
            default: "Pending", 
        }, 
    }, 
    { 
        timestamps: true, 
    } 
); 
 
module.exports = mongoose.model( 
    "Appointment", 
    appointmentSchema 
);

The status allows the progress of the appointment to be tracked: pending, confirmed, completed, or cancelled.

const paymentSchema = new mongoose.Schema(

16. User Model

The User model manages the user accounts of the platform. 

const userSchema = new mongoose.Schema( 
    { 
        name: { 
            type: String, 
            required: true, 
            trim: true, 
        }, 
 
        email: { 
            type: String, 
            required: true, 
            unique: true, 
            lowercase: true, 
            trim: true, 
        }, 
 
        password: { 
            type: String, 
            required: true, 
        }, 
 
        phone: { 
            type: String, 
        }, 
 
        role: { 
            type: String, 
            enum: [ 
                "admin", 
                "customer" 
            ], 
            default: "customer", 
        }, 
 
        isVerified: { 
            type: Boolean, 
            default: false, 
        }, 
    }, 
    { 
        timestamps: true, 
    } 
); 
 
module.exports = mongoose.model( 
    "User", 
    userSchema 
);

The role field distinguishes the two types of users:

  • admin: access to administrative features.
  • customer: access to customer features.

The isVerified field also makes it possible to determine whether the user account has been verified.

17. Handling Non-Existent Routes

app.use((req, res) => { 
    res.status(404).json({ 
        success: false, 
        message: `Route introuvable : ${req.method} ${req.originalUrl}`, 
    }); 
});

When an API URL does not exist, the server returns an HTTP 404 response.

18. Global Error Handling

app.use((err, req, res, next) => { 
 
    console.error("❌ Erreur serveur :", err); 
 
    res.status(err.status || 500).json({ 
        success: false, 
        message: err.message || "Erreur interne du serveur", 
    }); 
 
});

This middleware captures errors generated during request processing.

In the event of an internal error, the server generally returns the HTTP 500 status code.

19. Conclusion

The Solar Energy backend is organized around a modular architecture based on Node.js, Express and MongoDB.

Mongoose models structure data related to users, products, quotes, appointments, payments, contacts, and customer reviews.

The different API routes allow the React frontend to communicate with the backend and perform the operations necessary for the platform to function.
